# dct 手机端 第 0 期：局域网 —— 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 同一个 WiFi 下，手机扫一下终端里的二维码，打开一个网页，看见会话列表和**实时画面**，
并且能打字、能按 `Esc`/方向键/`Ctrl+C`。**没有服务器、没有账号、没有加密。**

**为什么先做这一期：** 手机端未知数最多的活（输入法、虚拟键行、40 列屏幕看 120 列画面、
拉帧频率）全都在客户端，跟传输无关。放在「改一行、刷新一下就看见」的环境里做，比放在
「改一行、部署一次、再掏手机」的环境里快一个数量级。而且它能回答那个真正的问题：
**你到底会不会在手机上用它。**

**跟第 1 期的关系：** 手机网页、spans 渲染、虚拟键行、输入法、`Request`/`Response` 全都
**原样复用**，第 1 期只换一根管子（直连 → 信封 + 中转）。这一期没有一行是白写的。

**Spec:** `docs/superpowers/specs/2026-08-23-dc-terminal-srv-design.md`
（决定四「手机没有 resize 权」、流控、断线三节在本期就适用；决定一/二/三是第 1 期的事）

## 这一期的安全边界（先读）

局域网模式下**数据不出你的网络**，所以 spec 决定二那套端到端加密在这里不需要。
但暴露面不是零——同一个 WiFi 上的任何人只要拿到 token 就能往你的终端里敲字。所以：

- **默认关闭。** 只有在设置页里打开「手机」时才监听，关掉立刻停掉监听线程。
- **token 是 32 字节随机数**，存 `~/.dct/secrets.toml`（0600 / Windows 单条 ACL，现成的）。
  每个请求都验，验不过一律 401，不给任何区分「token 错」和「没这个会话」的信息。
- **token 不进 URL 查询串。** 查询串会进浏览器历史、进任何中间日志。二维码里带的 token
  放在 fragment（`#t=…`，不上行），网页拿到后立刻用它换一个同源 cookie，地址栏里不留。
- **只在会话视图之外也能用**：这不是远程 shell，能做的事就是现有 `Request` 的子集。

## Tech Stack

**不加 web 框架，不加 async。** 需要的是 5 个路由加一个静态页面，`std::net::TcpListener`
加一个线程池够了——这跟仓库自己写 `sys/ipc`、自己写协议是同一个取舍。手写 HTTP 只支持
最小子集，并且**把子集写进代码注释里**：HTTP/1.1、只认 `Content-Length`（不支持 chunked
请求体）、响应固定 `Connection: close`。浏览器全都接受这个子集。

**唯一的新依赖是二维码。** 手机上手输 32 字节 token 不现实，二维码是必需品，不是装饰。
用纯 Rust 的 `qrcode` crate 生成矩阵，自己用半块字符（`▀`/`▄`）渲染到终端——渲染不外包，
因为终端画法要跟 `BarTheme` 那套配色和深浅背景对齐。

## Global Constraints

- **这份计划里的参考代码不是权威。** 照抄之前先想它对不对；测试通过之后做变异测试。
- **变异测试是每个任务的收尾动作**：判断取反、边界 ±1、`&&` 改 `||`，跑测试。
  没有测试失败 = 测试没写够。
- **200ms 的 tick 线程绝不碰网络**。HTTP 在自己的线程里。
- **HTTP 线程 panic 不许拖垮守护进程**（`catch_unwind`，同 `bridge.rs::spawn`）。
- **不发 `Resize`**（spec 决定四）：桌面 dct 是唯一有权改 PTY 尺寸的客户端。
- 网页上每一句话写给没编过程序的人；错误不给下一步就是没写完。中英双语。
- 不用 emoji 当图标。
- 测试可以绑 `127.0.0.1:0` 起真服务（仓库已有先例），但不碰公网。
- 每个任务结束前：`cargo test -- --test-threads=1`、`cargo fmt --check`、`cargo clippy --all-targets`。

## Tasks

### 任务 1：监听线程 + token　✅ 2026-08-24

- [x] `src/web/mod.rs`：监听 + 一连接一线程（并发上限 32，超了回 503 而不是闷掉）
- [x] 最小 HTTP/1.1 解析：请求行、头、`Content-Length` 请求体。**子集写进模块注释**
- [x] token：32 字节系统随机数，存 `secrets.toml`（`WEB_TOKEN_KEY`）；每请求校验；
      失败一律 401 且**逐字节一样**，不区分「路径不存在」和「令牌不对」
- [x] `catch_unwind` 包住每条连接
- [x] 13 条测试（绑 `127.0.0.1:0` 起真服务）
- [x] 变异测试 5 处，全部被抓：去掉 token 校验 / `same_secret` 的 `|=` 写成 `=` /
      忽略 `Transfer-Encoding` / body 长度上限放大 / 每次启动重新生成令牌

**三处跟原计划不同，都是故意的：**

- **绑哪个地址由调用方决定**，`serve()` 收一个已经绑好的 `TcpListener`。写死
  `0.0.0.0` 的话，测试会顺手把一个真的能从局域网连上的端口带起来——测试绑回环，
  守护进程在任务 5 里绑 `0.0.0.0`。
- **测试手写 HTTP 请求，不用 `ureq`**：要发的正是畸形请求（chunked、超长头），
  而一个正经客户端根本发不出来。
- **认证挪到路由之前**，并且加了一条「路由函数在未认证时根本没被调用过」的测试——
  只测「两条响应看起来一样」的话，一个先路由后认证的实现照样能过。

### 任务 2：只读路由　✅ 2026-08-24

- [x] `GET /api/sessions` → 现有 `List`
- [x] `GET /api/screen?id=N` → 现有 `Screen`（整屏 spans，差量是后面的事）
- [x] **路由层不新建业务逻辑**：只做「HTTP → `Request` → 现有 dispatch → JSON」，
      而且**答复就是协议本身的 JSON**，不另编格式——这是第 1 期能只换传输的前提
- [x] 8 条单测（假 dispatch）+ 4 条集成测试（`tests/web_routes.rs`，真 daemon 真 socket）
- [x] 变异测试 4 处，全部被抓：坏 id 缺省成 1 号会话 / 协议错误改报 HTTP 500 /
      未知路径回 405 / query 取值不比对键名

**两个定下来的规矩：**

- **`Dispatch` trait 是 `web` 和守护进程之间唯一的接缝。** `daemon::handle` 有八个
  参数，让 web 层去认识它们等于把两边焊死；trait 之后 web 只依赖一个函数，
  而测试塞个假的就能测路由。任务 5 里守护进程塞的是一个捕获了那些 `Arc` 的闭包，
  **不绕 socket**。
- **HTTP 状态码只描述 HTTP 这一层。** 路径不存在 404、方法不对 405、id 不是数字 400、
  令牌不对 401；而**协议层的回答一律 200**，包括 `Response::Error`——那不是「请求失败」，
  是守护进程给的一个正常答复（「这个会话不在了」）。混着用的话网页要写两条错误路径
  处理同一件事，迟早写得不一样。

**一处比计划更严的地方**：坏 `id` 就地 400，**不惊动守护进程**。缺省成某个会话的话，
一条打错的链接会安静地显示另一个会话的画面，而屏幕上没有任何线索。

### 任务 3：网页 —— 会话列表　✅ 2026-08-25

- [x] `src/web/page.html`：单页自包含（`include_str!` 进二进制），深浅色跟随系统，无外部资源
- [x] 卡片：会话名（没起过名就退回 profile）、状态、项目名、最后一行 activity
- [x] 空态、断线态都有话说
- [x] `GET /` 发网页，`GET /api/strings?lang=` 发文案表
- [x] 变异测试 5 处，全部被抓

**中途改掉的两件事：**

- **文案不写在网页里，从守护进程取。** 网页里一个用户可见的字都没有，全走
  `t("key")`，表由 `src/web/strings.rs::NEEDED` 定。理由是仓库既有的那条规矩
  （「决定用户看到什么字的地方只有一个，就是守护进程」）：网页里抄一份的话，
  `l` 键切了语言手机上不跟着变，`i18n.rs` 那两条守卫也查不到它。
  **两条守卫顶上**：网页里出现汉字就挂；网页取的键不在表里也挂。
- **「心跳断了写『你的电脑睡着了』」改成不那么肯定的说法。** 手机这一侧分不出
  「休眠了」「dct 关掉了」「换了 WiFi」，说死一种有三分之二概率在骗人。
  实际文案（`Key::PhoneOffline`）把三种可能都摆出来。

**任务 5 的一件事提前到这里做了**：fragment 里的令牌换 cookie。不做的话页面
根本打不开（见下），也就没法验收本任务。

**一个只有真打开浏览器才会发现的洞**：网页外壳原本也要令牌，而令牌在
fragment 里、**fragment 不会发给服务器**——第一次加载必然 401，于是永远执行不到
「换 cookie」那一步，自己锁死自己。所有单测都是绿的。修法是把 `GET /` 放进
免票名单（**只有它，且只有 GET**，有测试钉着），它是一段不含任何用户数据的
静态 HTML。

**验收方式**：`cargo test --test web_routes -- --ignored serve_for_a_manual_look`
起一个接**真守护进程**的本地服务，用浏览器打开看。这次实测到的：三个真会话的
名字/状态/项目/activity 都对、fragment→cookie 换成了、地址栏被清干净、
**页面转到后台之后轮询真的停了**（`document.hidden` 时不发请求）。
**没有实测到的**：断线提示和空列表提示的样子——那一刻标签页在后台、渲染器
冻着，只有字符串守卫覆盖着它们。

### 任务 4：网页 —— 实时画面　✅ 2026-08-25

- [x] 300ms 拉一次 `Screen`，**只在前台**；列表降到 3 秒一次（同一个定时器，一个计数器分频）
- [x] `ScreenSpan` → `<pre>` 里的一串 `<span>`，保留前景/背景/粗体/斜体/下划线/反显
- [x] 256 色索引照 xterm 的公式换算（跟 `ui::mod.rs` 那条对比度守卫同一套）
- [x] **按列数自动调字号**，让一整行放得进屏幕宽度；6px 封底，再小交给捏放大
- [x] 光标：`cursor_hidden` 为真时不画（桌面端踩过的那个"到处蹦的方块"）
- [x] **不发 `Resize`**（spec 决定四）
- [x] 变异测试 5 处，全部被抓

**「该不该发请求」收成了一处** `shouldPoll()`，有守卫钉着：`visibilityState`
在整个文件里只许出现一次，而且必须被调用两次以上（定义本身占一处——
这个洞是拿变异测试当场试出来的，只写 `>= 2` 的话定时器把判断整个删掉照样能过）。

**两条新守卫**，都是为了拦住 JS 这边测不到的东西：

- **`innerHTML` 在整个文件里禁用**（连同 `outerHTML`/`insertAdjacentHTML`/
  `document.write`）。屏幕内容是 agent 打出来的字节，当 HTML 用一次，
  一段 `<img onerror=…>` 就在这一页里跑起来了——而这一页的同源里躺着
  能往终端敲字的接口。规矩定成"整个文件不许出现"，一眼看得出真假。
- **协议名字对账**：拿 `ScreenColor`/`ScreenSpan`/`ScreenStyle` 真序列化一遍，
  名字必须在网页里出现过。Rust 这边改名而网页留在原地时，页面不会报错，
  只会安静地显示错东西（一屏没颜色的字）。

**两个只有打开浏览器才会发现的 bug：**

1. `{"Idx":0}` 是黑色，而 `if (c.Idx)` 对 0 是假的——一整屏黑字会被当成"没上色"。
   判断改成 `typeof c.Idx === "number"`，并且有变异测试钉着。
2. **`listEl.hidden = true` 没生效**：`[hidden]` 的 `display:none` 来自浏览器
   默认样式，而作者样式里任何一个 `display` 都比它优先——`main { display: grid }`
   把它顶掉了，于是进了画面之后列表还铺在下面。DOM 里 `hidden` 明明是 `true`，
   所有测试都是绿的。补一条 `[hidden] { display: none !important; }`。

**实测**（接真守护进程）：点开会话看到的就是这个 dct 会话自己的画面，124 段文字、
一半带颜色、字号自动缩到 13px、光标画在提示符上、返回键回列表、
后台时一帧不发。
