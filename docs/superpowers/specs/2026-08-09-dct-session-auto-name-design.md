# dct 给会话自动起名 —— 设计

**状态：** 待实现
**起因：** 2026-08-09 用户报「经常有串 session 的情况 —— 一个 session 的消息发给了另一个 session」。
根因是九宫格焦点漂移（独立 bug，见下面「前置」），但排查中暴露出第二件事：
**同一个项目挂着几个 `claude` 会话时，界面上写的是 `3 claude` / `5 claude`，用户根本分不出谁是谁**，
所以哪怕焦点没漂，他也没有办法在按下 Enter 之前确认自己在跟谁说话。
**关联：** `2026-08-06-dct-llm-connection-design.md` —— 本设计直接复用那一版落地的 LLM 层，
形状抄 `Request::Explanation` 那条路。

## 前置：焦点漂移修复（独立 bug，不在本设计范围）

用户报的「消息发错会话」有一个明确的、与命名无关的根因，必须**先修**：

`View::Grid` 的 `focus` 是一个位置下标，不是会话身份。看板列表的光标是按身份锚定的
（`refresh_rows()` 先取 `Anchor::Session(id, dir)`，重算后用 `find_anchor` 放回同一个会话身上，
`src/ui/app.rs:274-297`），而同一个函数对 `focus` 只做了一次越界夹取：

```rust
let grid_last = self.grid_sessions().len().saturating_sub(1);
if let View::Grid { focus, .. } = &mut self.view {
    *focus = (*focus).min(grid_last);      // src/ui/app.rs:301-304
}
```

`grid_sessions()` 会滤掉已停止的会话，所以**任何一个会话跑完变 `Stopped`，它后面的格子整体前移一位，
`focus` 静默指到别的会话上**。`i` 回一句的收件人取自 `visible.get(focus)`（`src/ui/grid.rs:205`）——
收件人在按下那一刻确实钉死成 id，但焦点在按下之前就已经漂走了。`Enter`（放大）、`s`（停止）、
`u`（回滚）走同一条路，后两个不可撤销。

这个漂移 `src/ui/mod.rs:1585-1590` 已经写着，当时只当成「`Enter` 放大错格子」，判定不在射程内。

**修法**：`refresh_rows` 里给 `focus` 用跟列表一样的身份锚定 —— 重算前记下
`grid_sessions()[focus].id`，重算后按 id 找回下标，找不到再退回现在的夹取。没有设计决策要定，
不需要 spec，直接进实施计划。

**命名不能替代这个修复。** 名字让「发错了」在按 Enter 前**看得见**，但它不阻止漂移。
把可见性当防线，等于把一个不可撤销操作的责任推回给用户。

## 问题

会话在界面上的身份是 `id + profile 名`：

| 位置 | 现在显示 |
|---|---|
| 九宫格格子标题 | `3 claude` |
| 列表行 | `3 claude` |
| 回复框收件人 | `回复 3 claude` |

一个项目开三个 claude 会话时，这三处写的东西完全一样，只差一个数字。用户记不住 3 号是哪个任务，
也没法在发消息前核对。`SessionInfo.activity`（屏幕最后一行）回答的是「此刻在干什么」，
每 200ms 变一次，**不是身份**，扫一眼认不出人。

### 为什么不是「截第一句输入的前 20 个字」

这是最便宜的方案，也是第一反应，但用户当场指出了它的毛病：**第一句经常没有意义。**
「继续」「帮我看看这个」、或者粘一大段需求进去而前 20 个字是「根据下面的需求，请你」。
一个八成时候没意义的名字比没有名字更糟 —— 它会让用户开始依赖它，然后在某一次依赖错。

所以主方案是**让模型起名**，第一句截断降为兜底。

## 范围

**要做：**

- 会话第一次干完活时，由 LLM 起一个 ≤12 字的名字，**钉死不再变**
- 四处显示改成 `id + 名字`
- 三级兜底：模型 → 第一句截断 → profile 名

**不做：**

- **不做用户手输/编辑的 tag。** 那需要一个新的 `Request`，旧守护进程不认，协议号必须升，
  而升号会踩到已知的坑：`ps`/`stop`/`kill`/`prune` 没接版本握手，碰到旧守护进程直接把
  serde 原文甩给用户；而重启守护进程会杀掉当时所有在跑的会话。用户明确选了「dct 自动打」。
- **不让名字跟着会话内容更新。** 会变的名字不是名字。「现在在干什么」已经由 `activity` 回答，
  用户缺的是一个稳定的身份。（用户明确选了「钉死」。）
- **不做重命名、不做搜索、不做按名字跳转。** 先看这个名字准不准，再谈围绕它建东西。

## 设计

### 1. 触发：第一次从 `Working` 落回 `Idle` / `Asking`

不在第一句输入发出去的那一刻起名 —— 那是信息最少的时刻，正是「继续」出现的地方。
等 agent 干完第一轮，屏幕上有它到底在做什么的实证。

只填一次。填过就不再问。**不需要 `explanation` 那套 generation 计数器** ——
那是因为失败会反复发生、迟到的旧答案会盖掉新答案；名字只产生一次，没有这个问题。

判据挂在已有的状态机上（`idle_pattern` / `busy_pattern` 每 tick 匹配 PTY 画面），
不新开一套检测。只对 `is_agent` 的会话做；shell 会话没有「干完一轮」这回事。

### 2. 采集第一句输入

守护进程侧 `send_input` 是唯一入口，两个客户端行为不同，都要接住：

- **会话视图**逐键转发，每个按键一次 `Request::Input`，回车到达时 `text` 是 `"\r"`
- **九宫格 `i` 回一句**先发整段 body，再发一次**空 `Input`**（空 = 按回车，
  见 `src/ui/grid.rs:600-612`）

所以 `Session` 上加一个 `first_input: String` 缓冲，累积规则：

1. 已经封存过就什么都不做
2. `text` 为空、或含 `\r` / `\n` → 把缓冲（连同这次 `\r` 之前的部分）封存，之后不再累积
3. 否则追加，**上限 200 字符**，超过就停止追加但不封存（粘一大段需求时，前 200 字足够喂模型，
   而把几千字留在内存里没有意义）

只在 `is_agent` 会话上累积。

**封存与否不影响起名**：起名那一刻直接读缓冲区当前内容。封存只决定「之后还追不追」，
不是「能不能用」—— 否则一个粘了几千字、还没按回车就被 agent 抢先干完一轮的会话会永远起不出名字。

### 3. 起名：抄 `request_explanation` 的形状

`src/session.rs:695` 那条路已经把所有难点解决过一遍，一模一样地再走一次：

```
name_slot: Arc<Mutex<Option<String>>>   // 跟 explanation_slot 平级
```

- **绝不在 tick 里同步等模型。** 那段注释的原话是「一次同步调用就能让整个守护进程卡住，
  而卡住的 dct 和死掉的 agent 长得一模一样」。起线程 + `complete_with_timeout`。
- 没配后端（`backend` 是 `None`）→ 直接返回，功能安静下线，会话照跑。
- 超时取 15 秒（比 `explanation` 的 30 秒短：那个是用户正等着看解释，这个是后台起名，
  没人等；等太久只是白占一个线程）。

**Prompt**（`name_prompt(first_input: &str, screen: &str)`，与 `explain_prompt` 并列）：

- system：要一个 ≤12 字的短名字，描述这个会话在做的**任务**，不是它此刻的动作；
  不要标点、不要引号、不要「任务」「会话」这类废词；
  **用与用户输入相同的语言**
- user：第一句输入 + 屏幕末尾 2000 字（`explain_prompt` 已经证明了只送末尾够用）

语言不做参数，写进 prompt。理由：名字由守护进程生成并**钉死**，而界面语言可以随时切
（`l` 键，切了不用重启 daemon）—— 任何「按界面语言生成」的方案都会在用户切语言之后
留下一堆对不上的名字。跟着**用户输入**的语言走，切界面语言也不会错。

**返回值要洗**：模型很可能回一句带标点的话或者加引号。取第一行、去首尾引号和标点、
按显示宽度截到 12 字。洗完是空串就当作失败，走兜底。

### 4. 三级兜底

1. 模型给出名字 → 用它
2. 没配 LLM / 超时 / 读不懂 / 洗完是空 → **第一句输入截断**（按显示宽度截到 12 字）
3. 连第一句都没有（shell 会话、或者用户还没说过话就先看板）→ 空串，界面画成今天的 `3 claude`

**前两级都发生在守护进程侧**，写进同一个 `name_slot`：触发那一刻先把第 2 级的截断值写进去
（同步、立刻可见），再起线程去问模型；模型答得出就覆盖，答不出就什么都不做，第 2 级的值留在那儿。
界面只认 `tag` 空不空，不参与兜底判断 —— 兜底逻辑放两份迟早分叉。

「只填一次」指的是**只触发一次这整套流程**：模型失败了也不在下一轮重试。重试要么把
「钉死」变成「会变」，要么需要一个「试过几次」的状态位，两个都比「名字偶尔退化成第一句」贵。

三级都不报错、不提示、不打断，跟 `explanation` 一样。

### 5. 显示

`SessionInfo` 加字段：

```rust
/// 会话的稳定名字，由守护进程在这个会话第一次干完活时起一次，之后不变。
/// 空串 = 还没起出来（刚建、没配 LLM、或者不是 agent 会话），界面退回 profile 名。
#[serde(default)]
pub tag: String,
```

**不升协议号。** 照 `proto.rs:334` 的 `scroll` 字段的先例：加纯读字段用 `serde(default)`，
旧 JSON 没这个字段时补空串；serde 反序列化默认忽略不认识的字段，所以旧界面 + 新守护进程
也不会炸。因为是自动起名，**不需要「设置 tag」这个新请求**，也就避开了上面「不做」里
写的那条升号代价。

代价：这个功能要等用户换上新守护进程才生效，新旧怎么搭配都不炸，只是没有名字。

四处显示，一律 `id + 名字`，profile 名让位：

| 位置 | 之后 |
|---|---|
| 九宫格格子标题 | `3 修登录白屏` |
| 列表行 | `3 修登录白屏` |
| 回复框收件人 | `回复 3 修登录白屏` |
| 会话视图标题栏 | 项目名 + `修登录白屏` |

`tag` 为空时四处都退回今天的样子。宽度不够时**先砍名字、保 id** —— id 是唯一不能丢的，
它是用户敲 `dct stop 3` 时用的东西。按**显示宽度**截，不按字符数（中文宽字符）。

## 测试

`llm/mod.rs` 的测试里已经有 `Fixed`（固定答案）和 `Slow`（超时）两个假后端，直接用：

- 状态从 `Working` 落回 `Idle` 后，`name_slot` 被填上假后端给的名字
- **只填一次**：再跃迁一轮，名字不变（这是「钉死」唯一能被测到的地方）
- 触发的那一刻 `name_slot` 立刻就是第一句截断值（还没等模型），模型答回来才覆盖
- `Slow` 后端 → 超时 → 名字停在第一句截断上；没有后端 → 同样停在第一句截断上
- 模型失败之后再跃迁一轮，**不重试**（`Fixed` 换成一个会答话的后端，断言名字仍是截断值）
- 第一句也没有 → `tag` 是空串，界面画出来还是 `3 claude`
- 采集：逐键送 `h` `i` `\r` 和一次性送 `"hi"` + 空 `Input`，两条路封存出同一个 `first_input`
- 采集：封存之后再送字，`first_input` 不变
- 采集：粘 300 字符，只留前 200
- 洗值：模型回 `"「修登录白屏」。"` → 洗成 `修登录白屏`；回一整段话 → 只取第一行并截断；
  回空白 → 当作失败
- 显示：窄终端下先砍名字、id 还在（跟仓库里已有的 80 列 / 60 列文案测试同一路子）

## 未决

- **名字准不准，只有实机能回答。** 上线后先自己用几天，看模型起的名字是不是真的能认人。
  如果经常不准，下一步是把 prompt 里的「屏幕末尾」换成「第一句输入 + agent 的第一条工具调用」，
  而不是急着加手动重命名。
- `explain_prompt` 的 system 是写死中文的（`src/session.rs:114`），而界面默认语言已经是英文。
  这是既有的、跟本设计同源的问题，本设计用「跟用户输入的语言走」绕开了它，
  **没有**顺手改 `explain_prompt` —— 那是独立的一件事。
