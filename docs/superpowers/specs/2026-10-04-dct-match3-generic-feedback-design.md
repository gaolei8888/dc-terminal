# dct 玩三消：不靠游戏知识，自己发现哪里不对（第四轮 · 通用机制）

日期：2026-10-04
前提：第三轮（`2026-10-04-dct-match3-ask-model-design.md`）已合入 main 并推送：规则没把握时问网关大模型，选不出就退回规则。

## 要解决什么

真机连玩第 1713 到 1716 关，反复遇到同一类事：dct 不知道自己错了。

- 第 1716 关：被笼子关着的糖，读出来像特殊糖，规则和大模型都被它骗；划下去游戏拒绝，dct 只知道「没反应」，下一次又选另一个笼子。
- 第 1715 关：连着划同一对格子，没反应，但它没意识到这些格子整体有问题。
- 所有关：dct 完全不知道「目标数字有没有降」，所以不知道一步到底有没有用。

这些不是某一个游戏的知识问题。要解决的是：**让 dct 不靠游戏知识，也能从「预测和实际对不对」「目标有没有动」里发现问题，并把发现告诉模型和记录。**

## 原则（2026-10-03 用户定的，仍然有效）

dct 只放通用代码；游戏专属的内容（彩球很强、笼子是什么、各关的经验、权重的具体数值）归 dcv 或配置文件，不写进 dct。本轮每一条都要能回答：**换一个别的方格游戏，这条还成立吗？** 成立才做。

## 做什么（全部通用）

### 1. 预测对不对

每一步划之前，规则已经算出「预计消几颗」。划完等画面停稳以后，比较棋盘实际变化：
- 预计会消、棋盘却和划之前一样（含「动一下又弹回」，已在 6248a5f 处理）→ 这一步涉及的格子**被拒绝**。
- 预计消 N 颗，实际变化的格子数远小于 N → 记一条「预测偏差」（只记录，不改行为）。

记录里加 `predicted_cleared` 和 `observed_changed`（棋盘里分组发生变化的格子数）。这是以后判断「我们的游戏模型哪里不对」的原料，对任何方格游戏成立。

### 2. 动不了的格子

被拒绝的那一步，涉及的两个格子里至少有一个是动不了的（不知道是哪个）。在棋盘发生变化之前，把这两个格子都当作**暂时不可选**（候选里排除所有碰到它们的步），不只是排除这一对。棋盘变了（别处的步成功了）就全部解除。

现在只排除「同一对」，所以第 1716 关的笼子一个个试，每个都要浪费一次。

连着没反应的停止上限从 2 放宽到 5（因为排除的是格子，不会重复试同一处；每次没反应只多等约 3 秒，也不扣步数）。

### 3. 只告诉模型看得见的事实

发给模型的候选句子里，**不写不可靠的猜测**。现在「引爆 N 颗特殊糖」是靠 dco 的 `odd` 标记猜的，笼子也会触发它，真机上把大模型带偏了。改成：
- 候选只写观察到的数字：互换哪两格、预计消几颗；
- 「特殊糖」相关的说法只在有可靠依据时才写；没有依据就不写，并在提示里加一句「棋盘上的特殊标记不一定准」。

具体哪些字段「可靠」由代码里一张小表决定，默认保守（不写）。

### 4. 读进度数字，看一步降了多少

顶部目标数字用 OCR 读（`see` 的文字），划前划后各读一次，差值写进记录的 `progress`（一个数字列表：画面上所有读得出的数，前后各一份，不解释它是什么）。哪个数字是目标，由用户给（`--goal-number` 指出第几个，或让 dct 自己看哪个数字在持续下降）；第一版只记录，不依赖它做决定。

这就是「攒数据」要的标签，也是以后训练选步、判断一步好不好的依据。

### 5. 停滞检测

连续 N 步（默认 6）进度数字没有下降（读不到进度数字时用「消掉的格子数」代替），就算**停滞**：
- 候选里的前几名都试过无效后，自动换办法：把发给模型的候选扩宽，并包含排名靠后的步；
- 没配模型就继续用规则，但在输出里说一句大白话「这几步看起来没有进展」。

第一版只做到：检测、记录 `stalled: true`、有模型就问一次。

### 6. 经验和题库的格式（只定格式，内容归 dcv）

- **经验**：`{局面特征, 走法, 效果}`（效果 = 进度差、是否被拒绝）。局面特征用通用的东西：棋盘字母图的哈希、候选的数字特征。
- **题库**：`{局面, 候选, 好的走法编号, 坏的走法编号}`，一行一条 JSON，和现有记录同一风格。`dct game ask-bench` 认这种带答案的文件时，除了「比乱选强多少」，还要报**选中好走法几个、选中坏走法几个**。

这一轮只定格式并让 `ask-bench` 认它；题目和经验的内容写进 dcv，不进仓库。

## 不做

- 带图问模型（等网关有读图准的模型）。
- 训练小模型（要先攒数据；见第三轮设计的「以后的方向」）。
- 任何游戏专属的规则：彩球加分、笼子识别、各关目标。这些是配置或 dcv 的数据。
- 改 dco。

## 测试

- 预测对不对：预计消、实际没变 → 被拒绝；实际有变化 → 不是；记录字段齐全。
- 动不了的格子：拒绝一步后，碰到这两格的所有候选都消失；棋盘变了以后恢复；上限 5 次后停，不再是 2 次。
- 候选句子：不含「引爆」「特殊糖」字样（除非有可靠依据）；提示里有「标记不一定准」。
- 进度数字：假 dco 的 `see` 返回前后两组数字，记录里 `progress` 对；读不到时不报错、字段为空。
- 停滞：连续 6 步无进展 → `stalled`；有进展就清零。
- `ask-bench` 认带答案的文件：统计选中好/坏的个数。
- 变异测试照老规矩跑在「格子级排除」和「停滞计数」上。

## 验收（真机，需要用户在场）

1. 第 1716 关（开局有笼子）：被拒绝一次之后，不再去试碰那两格的步；`--ask-model` 下大模型的候选里没有「引爆特殊糖」。
2. 记录里每一步有 `progress`（目标数字前后）和 `predicted_cleared` / `observed_changed`。
3. 把第 1715、1716 关里确定的好走法（开局两个彩球互换）和坏走法（笼子的步）做成一份带答案的题库（放 dcv，不进仓库），`ask-bench` 报得出好坏个数。

## 已知的限制

- 读目标数字靠 OCR，读不准时进度栏位只是记录，不影响玩。
- 「棋盘变化的格子数」是按分组比较的，特效动画会让它偏高；只用来发现「预计和实际差很远」，不当精确值。
- 停滞检测第一版只会「问一次模型」，更聪明的换办法是以后的事。
