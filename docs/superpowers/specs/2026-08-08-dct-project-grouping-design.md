# dct 看板按项目分组 —— 设计

**状态：** 待实现
**取代：** `2026-08-04-dct-board-project-scope-design.md` 全部（`Scope` 这套过滤模式被删除）
**影响：** `2026-08-05-dct-project-picker-redesign-design.md` 的选择器保留，但它的**触发语义**从
「换项目」降级成「加项目」

## 问题

2026-08-08 用户重新判定项目管理仍然混乱，要求「项目切换包括智能体切换一定要清晰，
让用户知道哪个项目用了哪个智能体」。

根因不是控件细节，是**三个互相独立的状态叠在一起，而屏幕上只写了其中一个**：

| 状态 | 存在哪 | 屏幕上 |
|---|---|---|
| 当前项目 `App.current_dir` | 内存字段 | 底栏边框标题一行 |
| 作用域 `App.scope`（本项目 / 全部） | 内存字段，`a` 键切 | 看板标题里 |
| 视图 `App.view_mode`（列表 / 九宫格） | 落盘，`g` 键切 | 不写 |

由此长出四个真问题：

1. **「当前项目」是个隐形模式，而且会被动改变。** 它同时管两件事——*看见什么*（过滤）
   和*下一个会话开在哪*（目标）。`enter_session`（`src/ui/mod.rs:893`）在你从「全部项目」
   进别人家的会话时会顺手改写它。于是 `n` 的结果取决于你几分钟前进过哪个会话，
   而那段历史屏幕上早就没了。
2. **项目不是一等对象。** 看板列的是会话。只看当前项目时路径列被主动删掉
   （`src/ui/board.rs:80`），也就是说**默认视图里项目名一次都不出现在行上**。
   想知道「哪个项目跑着哪个 agent」，得先按 `a`，再读一个截断到 22 列的路径。
3. **「上次用的 agent」是全局一个值。** `src/projects.rs:14` 只有一个
   `last_profile: Option<String>`。在 Grails 项目里用了 codex，切到 dc-terminal 按 `n`
   开出来的还是 codex。这一条直接顶着用户的要求。
4. **`a` 和 `p` 在解同一个问题的两半**，用户得自己在脑子里合起来。

## 范围

**要做：**

- 看板按项目分组，组头一行答完「这个项目跑着哪些 agent、有没有出错」
- 删除 `Scope` 过滤模式和 `a` 键
- 「当前项目」从可被静默改写的状态变成**光标所在组**的派生值
- `Tab` / `Shift+Tab` / `1`…`9` 一步换项目；`p` 降级为「加项目」；`x` 移除空组
- 每个项目记住自己上次用的 agent
- 底栏重做成三段：逃生键 / 当前项目 / 最多 3 个动作

**不做：**

- **不做「给项目钉一个默认 agent」的偏好设置。** 用户在选项里明确只要了「记住上次的」。
  「上次用的」已经覆盖 95% 的场景，多一个设置入口就多一处要解释的状态。
- **不做九宫格的真分组。** 格子是二维的，塞不进组头。那边只做排序 + 标签，见下。
- **不做项目别名 / 重命名 / 分类。** 目录名就是项目名。
- **不做跨项目搬迁会话。** 会话生在哪个目录就死在哪个目录。
- **不改 `p` 浮层本身**（`2026-08-05` 那版的左右分栏、git 标记全部保留），只改两件外围的
  事：它做完之后发生什么（pin 上看板，而不是切换当前项目），以及目录浏览器从哪儿开起——
  原来是 `current_dir.parent()`，现在是**当前组所在目录的上一级**，意图不变
  （「按 `p` 多半是想去旁边那个项目」）。

## 架构

### 一、分组是纯函数，视图状态是它的产物

```rust
// src/ui/view.rs

/// 看板上的一个项目组。
///
/// `sessions` 是这一组要显示的会话；已停止的会话在列表里显示、在九宫格里不显示，
/// 这个差异由调用方在传入前过滤（沿用现在 `visible` / `grid_visible` 的分工），
/// 分组函数本身不认识 `SessionState`。
pub struct ProjectGroup {
    pub dir: PathBuf,        // 归一化后的绝对路径，分组键
    pub name: String,        // dir.file_name()，组头上的项目名
    pub parent: String,      // short_path(dir.parent())，组头上的灰字
    pub sessions: Vec<SessionInfo>,
    pub last_profile: Option<String>,  // 这个项目上次用的 agent，底栏 `n` 那一条要用
    pub pinned: bool,        // 由 `p` 摆上来的（可以被 `x` 移除）
    pub collapsed: bool,
}

/// 看板上出现哪些项目：**有会话的 ∪ pinned 的**。没有第三种。
///
/// 排序按 `dir` 字符串升序，**固定**。任何按活跃度或最后使用时间的排序都会让行在
/// 用户没按键的时候移动，而那正是这一版要消灭的东西。
pub fn group_sessions(
    sessions: &[SessionInfo],
    pinned: &[PathBuf],
    profiles: &BTreeMap<PathBuf, String>,
) -> Vec<ProjectGroup>;
```

组头上的 agent 用量（`claude×2 codex×1`）和出错计数**从 `sessions` 现算**，不进结构体：
存下来就有两份真相，而它们只有一份是新的。

### 二、光标模型：一个扁平行列表

分组之后光标不能再是「第几个会话」——它得能停在组头上（空组只有组头）。

```rust
// src/ui/app.rs
pub enum Row {
    Header(usize),          // 组下标
    Session(usize, usize),  // (组下标, 组内会话下标)
}

pub struct App {
    pub groups: Vec<ProjectGroup>,
    pub rows: Vec<Row>,     // groups 展平的结果，折叠的组只贡献一行
    // list_state 选中的是 rows 的下标
}
```

**当前项目 = `rows[list_state.selected()]` 所属的那个组。** 不再有 `App.current_dir`
这个可以跟屏幕不一致的字段。

`App.start_dir` 保留，并且承担一件新职责：**`pinned` 为空时（全新安装、或者第一次跑
这一版），把 `start_dir` 补进去。** 这保证看板永远至少有一个组，光标永远有地方落，
`n` 永远有目标——「一个组都没有」这个状态在结构上不存在，不需要为它设计空屏文案。

### 三、光标钉住：这是本设计最关键的不变式

> 后台事件（会话结束、新会话出现、agent 出错）触发重新分组时，光标**必须停在原来那个
> 语义位置上**，不能因为行数变化而滑到别的项目上去。

`refresh_rows()` 的做法：重算之前先把当前行的**语义身份**存下来，重算之后再找回去。

```rust
enum Anchor { Session(u32), Header(PathBuf) }   // 会话按 id，组头按 dir
```

找回顺序：同 id 的会话行 → 该会话原属组的组头 → 同 dir 的组头 → 第 0 行。

配套的**组不塌陷**规则：一个项目的最后一个会话结束之后，它变成空组留在原地，
不会从看板上消失。组塌陷会让下面所有行上移，也就等于光标在用户没按键的情况下换了项目。
要它走，按 `x`。

### 四、换项目的五条规则

**规则 1 —— 看板上出现哪些项目：有会话的 ∪ pinned 的。**
`~/.dct/projects.json` 里那 20 条 `recent` 不再直接显示，它们只是 `p` 浮层里的候选。

**规则 2 —— 我在哪个项目：整组左侧一条竖色条**，从组头贯穿到该组最后一行。
不靠光标行、不只靠底栏一行字。

```
┌──────────────────────────────────────────────────────────┐
│ ┃ 1 ▾ dc-terminal      ~/work/dc   claude×2              │
│ ┃   ▶  3  干活中  claude   在改 src/ui/board.rs          │
│ ┃      7  等你    claude   要不要删掉 scope？            │
│   2 ▾ dc_classeditor   ~/work/dc   codex×1   ⚠ 1 出错    │
│        5  出错    codex    API Error: Connection clos…   │
│   3 ▾ dc_workbench     ~/work/dc   还没有会话            │
└──────────────────────────────────────────────────────────┘
```

会话行**不再重复项目名**——组头已经说了，省下的宽度还给 activity（现在屏幕上最先被
截断的那一列）。

**规则 3 —— 怎么换：**

| 键 | 动作 |
|---|---|
| `Tab` / `Shift+Tab` | 下 / 上一个项目，一步到位，光标落在组头 |
| `1`…`9` | 直达第 N 个项目（序号印在组头上；只有前 9 个组有序号，第 10 个起靠 `Tab`） |
| `↑` `↓` | 逐行走，走过组边界时项目跟着变 |
| `←` `→` / `Space` | 折叠 / 展开当前组 |
| `p` | 只在看板上还没有这个项目时用：浮层选目录 → 摆上看板 → 光标落进去 |
| `x` | 把空组从看板上拿掉（有会话的组拒绝，给一句提示） |

`Tab` 和数字键在看板和九宫格上是同一个键、同一个语义，跟 `g`/`n`/`p`/`c` 的现有约定一致。

**`p` 从「换项目」降级成「加项目」是这次最实质的一处改动。** 日常换项目是 `Tab`，
零模态、零浮层、一个键；浮层只在要去一个新地方时才出现。

**规则 4 —— 换完之后什么变了：** 只有两件，都写在屏幕上——`n` 落在这个项目
（底栏写着 `n 新建 claude`）；`u`/`s`/`d` 作用的会话在这个组里。**看见的会话不变**，
所有项目始终全在屏上。

**规则 5 —— 什么时候项目会自己变：只有你移动光标这一种。**
`enter_session` 里那段跨项目改写（`src/ui/mod.rs:893`）删掉：光标已经在那个会话行上，
也就已经在那个组里，天然一致。

### 五、底栏三段

```
Ctrl+Q 退一层 │ dc-terminal │ Tab 换项目  n 新建 claude  ? 更多
```

| 段 | 内容 | 让位吗 |
|---|---|---|
| 左 | 逃生键（现有 `escape_hint`） | 永不 |
| 中 | 当前项目名，按显示宽度截断到 14 列 | 永不 |
| 右 | **最多 3 个动作** + `? 更多` | 消息 / 断连提示可以顶掉 |

边框标题上那句「当前项目：<path>」**删掉**（`src/ui/mod.rs:1450`）——同一件事不写两遍。
中段常驻是对老 bug 的结构性修复：老版本里「已切到 X」这类消息会把项目信息整个顶掉。

右段按光标位置选，**上限硬性是 3 条，不随终端变宽而增加**——一行的内容随宽度变化，
本身就是不可预期：

| 光标在 | 右段 |
|---|---|
| 会话行 | `Enter 进会话  n 新建 claude  Tab 换项目  ? 更多` |
| 组头（非空） | `n 新建 claude  Tab 换项目  p 加项目  ? 更多` |
| 组头（空组） | `n 新建 claude  x 移除  Tab 换项目  ? 更多` |
| 九宫格 | `Enter 放大  Tab 换项目  n 新建 claude  ? 更多` |
| 会话里 | `F3 下一个会话`（键都归 agent，只剩这一个） |

剩下的 `u`/`s`/`d`/`c`/`g`/`l`/`q` 全在 `?` 浮层里。

**文字规则：** 说明 2–4 字、动词开头（`换项目` `新建` `进会话` `放大` `移除` `退一层`）；
段间用暗色 `│`，段内两个空格，**不再混用 `·`**；`n 新建 claude` 不加括号，这个项目
没用过 agent 就只写 `n 新建`；键名加粗，不用 emoji。

`widgets::fit_help` 的「按优先级丢」逻辑保留，但它现在是**兜底**而不是常态：3 条以内
在 80 列下永远放得下，丢弃只会在极窄终端里发生。

### 六、九宫格

真分组做不到，不假装能抹平。这边只做三件：

1. 格子标题**恒带项目名**（现在只在 `Scope::AllProjects` 下写，`src/ui/grid.rs:364`）：
   `▶ 3 claude 干活中 dc-terminal`
2. 格子按 `(dir, id)` 排序，**同一项目的格子连排**，翻页不打散一个项目
3. `Tab` / 数字键跳到该项目的第一个格子；焦点格所属项目写在底栏中段

空项目不占格子（格子是给活会话看的），但它在列表模式里看得见。

### 七、持久化与协议

`projects.json` 加两个字段，老文件照常能读：

```rust
struct Disk {
    #[serde(default)] recent: Vec<String>,           // 旧字段，留着，p 浮层的候选
    #[serde(default)] last_profile: Option<String>,  // 旧字段，留着当兜底
    #[serde(default)] pinned: Vec<String>,
    #[serde(default)] project_profiles: BTreeMap<String, String>,  // dir -> profile
}
```

`last_profile_for(dir)` = `project_profiles.get(dir)` 落空时回退到全局 `last_profile`。
这样老用户第一次升级不会突然发现每个项目都「没有默认 agent」，而每开一个新会话就
自动把那个项目的记录补上。

pinned 落盘而不是只活在内存里：规则 3 说了「`x` 才能移除」，不落盘的话重启 dct 就
自己没了，两句话对不上。

协议变更（`PROTOCOL_VERSION` +1）：

- `Request::LastProfile` → `Request::LastProfile { dir: String }`
- `Response::Projects(Vec<String>)` → `Response::Projects { recent: Vec<String>, pinned: Vec<String> }`
- 新增 `Request::PinProject { dir: String }` / `Request::UnpinProject { dir: String }`
- `Request::Create { remember: true }` 在 daemon 侧改为按 `dir` 记（`src/daemon.rs:256`）

### 八、i18n

新词条（`src/i18n.rs`）：`⚠ N 出错`、`x 移除`、`Tab 换项目`、`n 新建`、
「目录不在了」、「这个组还有会话，先停掉才能移除」、九宫格的「还没有会话，按 n 新建」。

删除：`BoardTitleAllProjects`、`NoSessionsAtAll` 及一切 `Scope` 相关词条。
`NoSessionsHere` 复用为**组头上**的「还没有会话」——「整个看板空着」那个状态不存在了
（见上面 `start_dir` 那段），不再需要它原来的语义。九宫格在所有组都没有活会话时
显示一句「还没有会话，按 `n` 新建」。

沿用既有约定：daemon 只报码，句子一律由界面组装。

## 要删的东西

删除比新增更能说明这次改动。以下全部移除：

- `view::Scope`、`view::visible_sessions`、`mod::toggle_scope`、`a` 键（看板和九宫格各一处）
- `App.scope`、`App.visible`、`App.grid_visible`、`App.current_dir`
- `mod::switch_project`
- `enter_session` 里的跨项目 `current_dir` 改写（`src/ui/mod.rs:887-900`）
- 底栏边框标题里的「当前项目：…」（`src/ui/mod.rs:1447-1454`）
- `board::draw` 里的 `show_dir` 分支与路径列

## 错误处理

- **项目目录被删了：** 组照常留在看板上，名字标灰，组头补一句「目录不在了」。
  会话本身还活着（进程的 cwd 已经打开），不动它。
- **`x` 一个非空组：** 拒绝 + 一句提示，不做「顺便停掉所有会话」这种复合动作。
- **daemon 版本不匹配：** 走现有握手流程，README 已有的「重启会结束正在跑的会话，
  问过你才动手」照常。
- **`projects.json` 读不出来：** 沿用现有做法当空处理，看板退化成「只有有会话的项目」，
  不影响可用性。

## 测试

- `group_sessions` 是纯函数：空输入、只有 pinned、只有会话、pinned 与会话重叠、
  同名不同路径的两个项目、被删目录、排序稳定性
- 光标钉住：会话结束后光标不跳组；新会话出现后光标不跳组；当前组变空后光标留在组头
- `Tab` 在最后一个组回绕到第一个；数字键越界不 panic
- `x` 拒绝非空组
- 底栏：左中两段在任意宽度、任意消息、断连状态下都不被顶掉；右段恒 ≤ 3 条 + `?`
- 每项目 agent 记忆：A 项目开 claude、B 项目开 codex 之后，两边 `n` 各自开对
- 老 `projects.json`（无 `pinned` / 无 `project_profiles`）能读，且全局 `last_profile`
  作为兜底生效
- 协议：新旧 `Request`/`Response` 的 JSON 快照测试（沿用 `src/proto.rs:637` 那条）

## 破坏性变更

两处，用户已知悉：

1. **`a` 键消失。** 分组之后没有「只看当前项目」这回事，肌肉记忆要改。
2. **`PROTOCOL_VERSION` +1。** 升级后旧守护进程需要重启，正在跑的会话会断
   （文件改动都在，agent 要重开）。走现有的询问流程。

## 已知上限

- 项目非常多（>10 个同时有会话）时，列表模式会被组头占掉可观的行数。折叠能缓解，
  但这个设计不为「几十个项目」优化——那不是 dct 的使用场景。
- 九宫格永远做不到跟列表一样清楚的项目边界。这是格子布局的固有代价，接受。
