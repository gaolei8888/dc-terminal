# 公开直播列表：固定地址上看得到老师选择公开的直播

日期：2026-09-13
状态：设计已确认，待写实施计划
关联：`2026-09-12-live-viewer-link-design.md`（本设计建立在它之上，不重复那边的决定）

## 要解决什么

今天的直播是「拿到链接才能看」：老师开播得到一条
`https://live.dataclue.cn/live/<房间号>#t=<令牌>`，必须一条一条发出去。用户要一个
**固定的公开地址**：打开 `live.dataclue.cn` 就能看到正在进行、并且被选择公开的直播。

用户在讨论中确认过的风险背景（不在本设计里再议）：强制直播学生工作区的能力已经
存在，公开地址会把被公开的屏幕暴露给整个互联网；面向公众的网络直播在国内有资质与
备案要求，由用户那边确认；中转和学生容器同住一台 8 GB 机器。

## 已确认范围

- **公开是逐场、显式选择的。** 默认私密，跟今天一样。管理台强制直播学生工作区时
  同样默认不公开。
- **列表内容：标题 + 路名 + 在看人数。** 路名常常是学生姓名，公开后会出现在公开列表上；
  管理台的确认框必须写明这一点。
- **只有持有发布密钥的人能公开。** 密钥由运营方在服务器上逐个签发、可单独吊销。
- **可控性**：直播中途随时能切回私密；能直接停播；运营方能吊销密钥、强制下线某一场；
  服务器有总开关。
- **公开期间屏幕上说「正在公开直播」**，跟私密直播区分开。

不在这一版：公开观众登录/白名单、管理台里的密钥管理界面、缩略图预览、公开页搜索与
分类、回放。

## 为什么是「中转管公开」

讨论过三条路：

- **A. 中转给房间加一个「公开」标记（选定）**。公开期间无令牌可读，切回私密即时生效，
  私密链接不受影响，流量不经过管理台。
- **B. 管理台做公开页并转发画面**。所有公众流量压在管理台进程上（内存上限几百 MB），
  老师本机按 `L` 开的播还要另开一条通道登记到管理台。
- **C. 公开页直接列出带令牌的私密链接**。改动最小，但公开一次令牌就给了所有人，收回
  只能换令牌，已发出去的私密链接全部作废——违背「能随时收回」。

## 一、中转（`dct-srv`）

### 发布密钥与总开关

- 启动参数 `--publish-keys <文件>`。**不带就没有公开功能**：公开接口一律拒绝，
  公开页显示空列表。这就是总开关，也是回滚手段。
- 管理命令（直接改文件，不走网络）：
  - `dct-srv key add <名字> --file <文件>`：生成一把密钥，**只打印这一次**，文件里存
    `名字 + SHA-256 摘要 + 创建时间`。
  - `dct-srv key revoke <名字> --file <文件>`、`dct-srv key list --file <文件>`。
  - `dct-srv takedown <房间号> --file <文件>`：把房间号写进同一文件的黑名单。
- 运行中的中转每 10 秒检查文件修改时间，变了就重新加载。**吊销、下线最多 10 秒生效**：
  重新加载后，由已吊销密钥公开的房间、以及黑名单里的房间，立刻变回私密。
- 密钥比对沿用现有的常数时间比较。文件权限 0600，属主 root。
- 文件解析失败时**保留上一份有效内容**并在日志里报错——不能因为手滑写坏文件就把所有
  密钥当成吊销，也不能当成全部放行。首次启动就解析失败则拒绝启动。

### 公开 / 取消公开

```
PUT    /live/{id}/public   { "title": "...", "key": "<发布密钥>" }
DELETE /live/{id}/public
```

两条都要证明「你控制这场直播」，二选一：

- `x-live-push: <推帧钥匙>`（老师本机的守护进程直接调用），或
- `x-live-grant: <凭证>`（管理台代学生工作区调用，见「凭证」）。

`PUT` 另外要验发布密钥。规则：

| 情况 | 答复 |
| --- | --- |
| 房间不存在，或推帧钥匙/凭证不对 | 401（跟今天推帧、停播同一个码，不给探测差别） |
| 服务器没开公开功能（没带 `--publish-keys`） | 403 |
| 发布密钥不对或已吊销 | 401 |
| 房间在黑名单里 | 403 |
| 标题为空或超过 60 个字符 | 413 |
| 按来源限流超限（跟建房共用 `note_start` 那本账） | 429 |
| 成功 | 204 |

- 公开状态挂在房间上：`public: Option<{ title, key_name }>`。重复 `PUT` 覆盖标题。
- `DELETE` 对未公开的房间也回 204（幂等）。
- 房间被停播或 `LIVE_TTL` 回收时公开状态随房间一起消失。
- **重开同一个房间号（`POST /live/start`）不继承公开状态**：谁要公开谁重新 `PUT`，
  由各自的自愈逻辑负责（见第二、三节）。

### 凭证

`grant = hex(HMAC-SHA256(key = SHA-256(push_secret), message = "publish:" + id))`

- 中转手里本来就存着 `SHA-256(push_secret)`（`Session::push_hash`），能验证；推帧钥匙
  原文始终不离开守护进程。
- 凭证**只能用于 `PUT/DELETE /live/{id}/public`**，推帧、停播都不认它。
- 计算函数放在 `dct-link`，中转和守护进程调用同一份实现，并用一组固定的测试向量钉住。

### 无令牌观看

- `GET /live/{id}/frame`、`GET /live/{id}/lanes`：请求**没带** `x-live-token` 时，房间
  公开就放行，否则 401。
- 带了令牌照旧校验令牌——带错令牌的请求**不会**因为房间公开而被放行。
- 私密房间、不存在的房间、黑名单房间对无令牌请求回同一个 401。
- `GET /live/{id}/lanes` 的答复增加 `public: { "title": "..." } | null`。推帧线程本来就
  搭保活那一拍查这条路由拿人数，顺带把公开状态带回守护进程（见第二节）。

### 公开列表

- `GET /live/public` → `[{ "id", "title", "lanes": [...], "viewers" }]`，按在看人数
  降序。**不含发布者**（发布者只在服务器上 `dct-srv key list` / 日志里可查）。
- `GET /` → 公开页（第四节）。
- 这两条挂在直播路由组里（`Routes::LiveOnly` 也有），`/link/*` 仍然只在 `--with-link`
  下出现。
- **`public` 是保留字**：`POST /live/start` 拒绝房间号 `public`（401，同其他不合规的
  房间号）。不拒的话，那场直播的观看页 `/live/public` 会被列表接口挡住。

### 部署侧

- Caddy 白名单在 `/live/*` 之外精确放行 `/`，其余一律 404。验收：`/` 200，
  `/link/poll`、`/link/send`、`/link/ask` 404。
- 上限沿用：房间 64、每场 4 路、每帧 256 KB。公开观众数不单设上限，靠现有的文件句柄
  配置（`docs/deploy-live-relay.md`）。

## 二、老师这一侧（dct）

### 设置页与密钥存放

- 设置页新增「公开直播密钥」一项，交互同 API 密钥（输入不回显）。存进密钥仓，保留键
  `__live_publish__`（同 `__gate__`、`__web__` 的做法）。
- **密钥只在守护进程里用**。界面进程只知道「已填 / 未填」，任何经过协议线的请求、响应
  和 `Debug` 输出里都不出现它。

### 直播面板

- 新增 `p`：公开 / 取消公开。公开时弹一行标题输入（预填上次用过的标题），Enter 确认，
  Esc 取消。
- 没填密钥：`p` 直接提示「先到设置页填公开直播密钥」，不发请求。
- 面板显示公开状态：私密 / 正在公开… / 已公开 · 标题 / 公开失败（原因）。
- 公开失败的原因由码组句，两种语言：密钥无效或已吊销（401）、服务器没开公开功能或
  这场被下线（403）、标题太长（413）、太频繁（429）、连不上中转。

### 底栏常驻提示

- 私密：`● 正在直播 · 2 路 · 7 人在看`（不变）。
- 公开：`● 正在公开直播 · <标题> · 2 路 · 7 人在看`。
- 公开失败：这一行用错误样式（实色底栏上是 `bar_danger`），直播本身不停。
- 实色底栏守卫测试（`nothing_on_a_solid_bar_takes_its_color_from_the_terminal_theme`）
  增加「正在公开直播」一屏。

### 守护进程

- `LiveState` 记住「期望的公开状态」（`None` 或 `Some(title)`）和「实际的公开状态」。
- 推帧线程在 `start_room` 成功之后，若期望公开，就用推帧钥匙 + 发布密钥调 `PUT`；
  房间因为中转重启或回收被重开后同样再调一次——**断线自愈**。
- 实际状态以中转为准：每次 `fetch_viewers` 把 `/lanes` 答复里的 `public` 写回。这样
  管理台代为公开的直播，学生屏幕上也会显示「正在公开直播」，**最多延迟一次保活间隔
  （`KEEPALIVE`，20 秒）**，再加界面每 2 秒一次的轮询。
- 自愈规则，**只有一条**：本机期望公开、中转却说不公开（中转重启、房间被回收、密钥被
  吊销、被下线，这几种情况守护进程分不出来，也不需要分），就**再调一次 `PUT`**，由那次
  答复决定结果：
  - 204 → `Listed`；
  - 401 / 403 / 413 → `Failed { reason }`，**不再重试**，直到老师自己再按一次 `p`。
    运营方的吊销和下线不能被自愈悄悄绕回去，也不能让守护进程每 20 秒去撞一次中转；
  - 连不上 → `Failed { Unreachable }`，按现有的开播退避（`START_BACKOFF`）重试。
- 期望不公开的直播（包括管理台代为公开的），守护进程只照实显示中转说的状态，从不自己
  去调 `PUT`；管理台公开的由管理台自愈（第三节）。

### 协议（`PROTOCOL_VERSION` 18 → 19）

- `Request::LivePublish { title }` → `Response::Live(LiveInfo)`。守护进程用自己的密钥；
  没有密钥回新错误码 `ErrorCode::LivePublishKeyMissing`。
- `Request::LiveUnpublish` → `Response::Live(LiveInfo)`。
- `Request::LivePublishGrant` → `Response::LiveGrant(String)`；没在播回
  `LiveStagingRejected(NotLive)`。
- `LiveInfo` 增加 `public: LivePublic`：`Private | Pending { title } | Listed { title } |
  Failed { title, reason: LiveFailure }`。
- 钉线上形状的测试同步到 19。旧守护进程收到新请求回的 `unknown variant`，管理台沿用
  「这个工作区的 dct 版本还不支持」那句提示。

## 三、管理台（`container/classroom`）

### 配置

- `CLASSROOM_LIVE_PUBLISH_KEY_FILE=/etc/dcw-classroom/live-publish.key`（0600，root）。
  **不用环境变量直接放密钥**：环境变量会出现在 `systemctl show` 里。
- 没配这个文件，管理台不显示任何公开相关的控件，接口回 404。
- 中转地址用已有的 `CLASSROOM_LIVE_RELAY`。

### 操作

- 「直播这个工作区」确认框增加「同时公开」勾选框（默认不勾）。勾上要填标题（预填
  `<学生名> 的工作区`），并写明：**学生姓名和屏幕会出现在 live.dataclue.cn 的公开列表上，
  任何人都能看。**
- 直播中「更多」菜单增加「公开这场直播」/「取消公开」，同样确认、填标题。
- 行内状态：`● 公开直播中 · <标题> · N 人在看`；私密仍是 `● 直播中 · N 人在看`。

### 公开流程

1. `driver.rpc(w, 'LivePublishGrant')` 拿凭证；
2. 用凭证 + 管理台自己的发布密钥 + 标题调 `PUT /live/{id}/public`（房间号从
   `LiveStatus` 的链接里取）；
3. 在 store 里记下 `w.livePublic = { title }`，写审计。

取消公开同理调 `DELETE` 并清掉记录。停播时清掉记录。

### 自愈

- 后台每 30 秒检查所有 `livePublic` 不为空的工作区：守护进程说在播、中转说不公开，
  就重新走一次公开流程。
- 中转回 401（密钥被吊销）或 403（下线 / 总开关关）时**不再重试**，清掉记录并在该行
  显示原因——运营方的吊销不能被自愈悄悄绕回去。
- 守护进程说没在播：清掉记录。

### 错误提示

| 情况 | 提示 |
| --- | --- |
| 中转 401 | 发布密钥无效或已吊销 |
| 中转 403 | 服务器没有开启公开直播，或这场直播已被下线 |
| 中转 413 | 标题太长（最多 60 个字） |
| 守护进程不认识 `LivePublishGrant` | 这个工作区的 dct 版本还不支持，请先停止它再启动（会换成新镜像） |

### 审计

「公开直播工作区」「取消公开直播」「公开直播被中转拒绝（原因）」写进现有审计日志，带
管理员、工作区、标题。

## 四、公开页与观看页（`dct-page`）

### 公开页 `public.html`（`GET /`）

- 标题「正在公开直播」，每场一张卡片：标题、路名、`N 人在看`；点击进入 `/live/{id}`。
- 空列表显示「现在没有公开直播」。
- 每 5 秒拉一次 `/live/public`；`document.hidden` 时暂停，回到前台立刻拉一次。
- 语言按 `navigator.language` 选一次，同 `live.html`。
- **标题和路名只能用 `textContent` 写进页面。** 它们是老师或管理台填的自由文本，
  用 `innerHTML` 拼就是公开页上的存储型 XSS。守卫测试：`public.html` 和 `live.html`
  的源码里都不出现 `innerHTML`（`live.html` 现在也没用它，这条测试顺带把它钉住）。
- 不设 cookie，不带 referrer。

### 观看页 `live.html`

- 地址里没有 `#t=` 时不带令牌请求；公开房间正常播放。
- 无令牌播放中收到 401：显示「这场直播已结束或不再公开」和「回到公开列表」链接。
  中转对「停播」和「切回私密」回同一个 401，页面不猜是哪一种。
- 带令牌的私密链接行为不变。

## 测试

**中转（Rust）**
- 密钥文件：加载、`key add/revoke/list`、10 秒重载生效、坏文件保留旧内容、首次启动坏文件拒绝启动。
- `takedown`：黑名单房间公开被拒、已公开的在重载后变私密。
- `PUT/DELETE` 鉴权矩阵（上表每一行），推帧钥匙和凭证都能用，凭证不能推帧、不能停播。
- 无令牌读：公开放行、私密/不存在/黑名单同一个 401、带错令牌不因公开而放行。
- 房间号 `public` 被 `POST /live/start` 拒绝。
- 列表：内容与排序、不含发布者、停播与 TTL 回收后消失。
- `/lanes` 答复带 `public`。

**凭证（`dct-link`）**
- 固定测试向量；中转与守护进程调用同一函数。

**dct（Rust）**
- 协议形状钉到 19；发布密钥不出现在任何序列化结果和 `Debug` 输出里。
- `LivePublish` 无密钥回 `LivePublishKeyMissing`；有密钥时推帧线程发出 `PUT`（假中转断言请求）。
- 自愈：期望公开而中转说不公开时补一次 `PUT`；答复 401/403 后不再重试；连不上时按
  退避重试；期望不公开的（含管理台公开的）从不自己调 `PUT`。
- `/lanes` 的 `public` 写回 `LiveInfo`。
- 面板 `p` 键流程、两种语言文案、底栏公开提示、实色底栏守卫。

**管理台（Node）**
- 没配密钥文件：无控件、接口 404。
- 公开：先 `LivePublishGrant` 再 `PUT`，带对凭证、密钥、标题；审计。
- 错误码到提示的映射；旧 dct 的 `unknown variant`。
- 自愈：中转重启后重新公开；401/403 不重试并清记录。

**公开页**
- `innerHTML` 守卫；手工验收脚手架（起中转 + 公开页，眼睛看）。

每条新测试做变异检查：把对应实现改坏，测试必须失败。

## 前置条件

**CI 的 Windows 一格必须先修绿。** `release.yml` 依赖 CI 通过，Windows 红着的时候这个
功能做完也发不出版本。

## 部署（dataclue.cn，按顺序）

1. **中转**：新源码重编 `dct-srv`；`dct-srv key add 管理台`，再给每位老师各签一把；
   systemd `ExecStart` 加 `--publish-keys /etc/dct-srv/publish-keys`。
2. **Caddy**：精确放行 `/`；跑验收（`/` 200，`/link/*` 404）。
3. **管理台**：写 `/etc/dcw-classroom/live-publish.key`（0600），设
   `CLASSROOM_LIVE_PUBLISH_KEY_FILE`，更新代码，重启。
4. **镜像**：构建协议 19 的工作区镜像，确认 `CLASSROOM_LIVE_RELAY` 已配，逐个工作区
   停止、启动。
5. **老师**：升级本机 dct（守护进程重启一次），设置页填发布密钥。

**回滚**：中转去掉 `--publish-keys` 重启——公开列表清空、公开接口拒绝；私密直播与其余
功能不受影响。

## 待定

- 标题上限 60 字、列表刷新 5 秒、密钥文件重载 10 秒、管理台自愈 30 秒：按这组数实施，
