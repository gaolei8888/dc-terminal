# dct 玩三消：新关卡由对话里的 AI 认棋盘（第二轮 · 第二步）

日期：2026-10-03
前提：第一轮（`2026-10-02-dct-match3-play-design.md`，一关里读棋盘、选步、划）和第二轮第一步（`2026-10-03-dct-match3-next-level-design.md`，`--auto-next`：失败重来、安全弹窗、遇到钱/广告/没生命/通关/不认识就停）都已合入 main，v0.2.24 已发布。

## 要解决什么

每一关的棋盘位置、行列数、障碍都不一样。第 1712 关是 5 列 9 行；第 1713 关（2026-10-03 真机）是 9 列 9 行，顶部中间有缺口，大半格子被蜂蜜块盖着，两边有糖果机。按 1712 的位置去读 1713，读出来是乱的，所以第一步里「通关就停，不进下一关」。要真的一关接一关，每个新关卡都要先**认一次棋盘**：

1. 棋盘在窗口的哪一块、几行几列；
2. 哪些颜色是糖，哪些**不是糖**（缺口、蜂蜜块、糖果机）。

## 用户定的（2026-10-03）

- **方案 A：让对话里的那个大模型自己看截图认**（Claude Code、Codex、千问；它们本来就能看图），dct 提供检查和保存的工具。不走 B（dct 自己调带图的大模型：要网关密钥和能带图的模型，现在都没有），不走 C（纯算法找格子）。
- 每个新版面认一次，花对话 AI 几十秒；认好存起来，以后同一关直接用，玩的时候不再用大模型。

## 真机证据（第 1713 关，2026-10-03，已存 `crates/dct-game/tests/fixtures/candy-1713-live.json`）

用手工量出的位置（区域 x 0.024、y 0.311、宽 0.949、高 0.467，9 行 9 列）读一次，**对着截图逐格核对过**：前 5 行每一格都对，后 4 行全是蜂蜜块。dco 返回 7 个类别：蓝、紫、红、绿、黄五种糖，加两个「不是糖」的：
- 类别 D（41 格，颜色 196,148,101）：蜂蜜块**和**顶部的缺口读成了同一种；
- 类别 E（6 格，颜色 161,180,233）：左右两边的糖果机。

结论：AI 看完截图，只要告诉 dct「D 和 E 不是糖」就够了；最大的类别占 41/81 = 51%，在第一轮加的「任何颜色超过 70% 就不是棋盘」的限度内，不会被误拒。

## 做什么

### 1. 三个命令（给对话里的 AI 用，也给人用）

- **`dct game look [--game 名字] [--region x,y,w,h --rows R --cols C]`**：读一次，用大白话打印——当前关卡号（读画面上的字，如 `1713/♥5` → 1713）、用的是哪份配置、颜色类别表（字母、颜色名、数量、是不是糖）、把棋盘按字母画成文字（行列从 1 数）、「像不像棋盘」的判断。AI 拿它对着截图核对。不带 `--region` 就用已存的配置（没有就用默认的）。
- **`dct game save --game 名字 --region x,y,w,h --rows R --cols C [--fixed D,E]`**：用这组位置读一次，通过检查才保存到 `~/.dct/games/<名字>.toml`；`--fixed` 列出「不是糖」的类别字母（取自 `look` 打印的表）。
- **`dct game list`**：列出已经认过的关卡。

### 2. 按关卡号自动找配置

`dct game play`（不带 `--game`）：先读画面上的关卡号，找 `~/.dct/games/level-<号>.toml`；找到就用；找不到就**停下并说**「这一关（1713）还没认过棋盘。请按说明卡里「新关卡」的步骤认一次，再运行」，退出码 0，停止原因 `needs_calibration`，并记一行 `kind:"nav"`、`screen:"needs_calibration"`（带关卡号和画面上的字）。这就是触发 AI 去认的信号。读不出关卡号时退回内置的第 1712 关配置（和以前一样）。内置的 1712 配置也以 `level-1712` 的名字对外显示，不改行为。
`--game 名字` 仍然优先，显式指定就不看关卡号。`--auto-next` 同理：通关后进入下一关，换一个关卡号，就按新关卡号找配置，没有就停，AI 认完再运行。

### 3. 配置格式（TOML，在第一轮的字段上加类别表）

```toml
window = { app = "iPhone Mirroring" }
region = { x = 0.024, y = 0.311, w = 0.949, h = 0.467 }
rows = 9
cols = 9
odd_share = 0.15

[[class]]
name = "蜂蜜块和缺口"
rgb = [196, 148, 101]
kind = "fixed"          # fixed = 不是糖：不能换、不连线、挡住下落

[[class]]
name = "糖果机"
rgb = [161, 180, 233]
kind = "fixed"
```

- 只记 `kind = "fixed"` 的类别（颜色）。没记的类别都当糖。
- **玩的时候**：dco 每次读棋盘返回的类别编号会变，所以按**颜色**对应：读到的每个类别，找配置里颜色最近的 `fixed` 类别（Lab 颜色距离 ≤ `class_de`，默认 24），对上了就是 fixed，对不上就是糖。
- 兼容：没有 `[[class]]` 的旧配置（第一轮的）照常工作。

### 4. 选步要认识「不是糖」（`crates/dct-game`）

加 `Cell::Fixed`：不能被换，不参与连线（它会截断一条线），**挡住下落**（糖只在同一列里两个 fixed 之间的一段内往下掉，不穿过去；每一段上面新补进来的是未知）。其余规则不变。这一步**不处理**：蜂蜜块被旁边的糖消掉时的清除/扩散、各种关卡目标（收集、清蜂蜜）的得分——还是第一轮那套「消得多、做特殊糖」。第 1713 关的目标是清蜂蜜，规则选步不会偏向它，只保证不乱换、不白划；目标感知的打分是以后的事。

### 5. 说明卡加一节「新关卡」

卡里写给 AI 的步骤：运行 `dct game play` 看到「还没认过棋盘」→ ① 用 dco 截一张当前画面（`DCO_IMAGE_OUT=文件 dco call see '{"window":{"app":"iPhone Mirroring"},"include_image":true}'`）并看图；② 估计棋盘的范围（窗口比例）和行列数；③ 运行 `dct game look --region … --rows … --cols …`，把打印的字母棋盘和截图逐格对，错了就调整再 look；④ 对上以后，认出哪些类别不是糖，运行 `dct game save --game level-<号> … --fixed …`；⑤ 再运行 `dct game play --dry-run` 看第一步合不合理，没问题再真玩。强调：**不要猜**，对不上就继续调，调不出来就告诉用户；不点游戏里的任何按钮。

## 不做

- dct 自己调大模型（B）、纯算法找棋盘（C）。
- 记忆库（dcv）的游戏资料格式（`dcv games`）：dc-vault 那边有草稿，等这一步在本机跑通后再对接；截图指纹的存取等那时再做。
- 目标感知的打分、蜂蜜块扩散、传送带、糖果机出糖等关卡机制。
- 自己点关卡按钮（只有数字，dco 不让点）、道具圆泡（没有字，dco 不让点）：从地图进下一关仍然是用户的事。

## 测试

- **颜色对应**：编号被打乱仍对得上；颜色有小偏差（RGB 各差几个点）仍对得上；差得远的不算；没有 `[[class]]` 的旧配置不变。
- **`Cell::Fixed` 的模拟**：不被换、不连线（截断线）、挡住下落、一段内的下落正确；第 1713 关真读数（`candy-1713-live.json`）加上 D、E 为 fixed：合法交换的全集由人核对后钉进测试，所有交换都不涉及 D、E 的格子。
- **`look` 的输出**：用 1713 的真读数打印，格式和大白话钉死；关卡号解析（`1713/♥5`、`1713 / ♥5`、没有数字的画面）。
- **`save`**：拒绝头重脚轻的读数（70% 规则）、拒绝行列和区域对不上的、写出的文件能被 `profile::load` 读回、`--fixed` 里写了不存在的字母要报错。
- **`play` 的关卡号查找**：有配置用配置；没有就停（`needs_calibration`，不划、不点）；`--game` 优先；读不出关卡号退回内置。
- **假 dco 的集成测试**：`look`、`save`、`play` 缺配置的整条命令。
- 变异测试照老规矩跑在颜色对应、Fixed 的下落、关卡号查找上。

## 验收（真机，需要用户在场）

1. 现在屏幕在第 1713 关：我（控制者，扮演对话里的 AI）照说明卡的步骤认一次：截图、look、对、save。
2. `dct game play --dry-run` 的第一步合理；真玩 20 步：没有划到蜂蜜块或糖果机、没有「划了没反应」连着出现。
3. 在 Claude Code、Codex 里各说一句「帮我玩这一关」：它们走完「认棋盘」再玩（千问有网关密钥以后再测）。
4. 通关后用 `--auto-next` 进入下一关时，因为没有那一关的配置，应该停在「还没认过棋盘」。

## 已知的限制

- 关卡号靠画面上的字（OCR）。读不出来就退回第 1712 关的配置，那可能是错的：`look` 会在打印里明说「没读到关卡号」。
- 认得对不对取决于对话里那个 AI 看图的准确度；`look` 的字母棋盘是它和截图对照的依据，`save` 的检查只挡明显不对的（70% 规则），挡不住「位置偏了一格但颜色分布看着像」。所以说明卡要求逐格对。
- 只做 Candy Crush 这一类方格三消；别的游戏要自己写配置。
