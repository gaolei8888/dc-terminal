# 让大模型教会本地小模型玩游戏

日期：2026-10-04
状态：设计，待用户审；没有代码。
起因：用户 2026-10-04 要求「必须能玩」《Darkness and Flame》这类寻物游戏，并说「你想办法让大模型教会我们的本地小模型」。用户明确要用 Claude 当老师（理由：这只是个会点游戏的小模型，不是通用模型）；条款怎么解释由用户核对，设计里每条数据都标明来源，训练时可以按来源过滤。

## 目标

本地小模型（先用 Qwen3-VL-4B + LoRA 补丁，Mac 2 上已有读棋盘的先例）在一个游戏里，**看着画面决定点哪里**，成功率逐步接近大模型，大部分步不再需要大模型。平时玩靠小模型（本机、免费、不上传），小模型没把握时才问大模型，老师的每次回答又成为新的教材。

## 为什么不是「录一批数据训一次」

只记老师的正确操作再训，小模型学到的是老师走过的那条路；它一上场就会走到老师没走过的画面，不知道怎么办。更有效的办法是让小模型自己玩，**在它走到的画面上由老师纠正**（这是模仿学习里常说的 DAgger）。所以流程是循环：

1. 老师玩，记录；
2. 用记录训练小模型；
3. 小模型玩，老师在它**卡住或点错**的地方纠正；
4. 纠正的数据加进教材，回到 2。

## 记录格式（一步一条，教学和训练共用）

放在 `~/.dct/learn/<游戏名>/<日期>/steps.jsonl`，图片放同目录 `png/` 下。**整个目录不进 git、不上传。**

```json
{
  "schema": 1,
  "game": "darkness-and-flame",
  "time_ms": 0,
  "screen": { "png": "png/0012.png", "texts": ["5+", "4/6", "HINT", "MENU"], "numbers": [5], "genre": "hidden_object" },
  "action": { "kind": "tap_at", "x_bp": 1900, "y_bp": 5800 },
  "teacher": "claude",
  "rationale": "箱子在圆房间里，应该先点它",
  "outcome": { "changed": true, "change": 0.31, "settled_ms": 640, "numbers_after": [5], "progress": "inventory 4/6 -> 4/6" },
  "label": "effective" 
}
```

- `teacher`：`claude` / `qwen` / `user` / `student`（小模型自己选的）。训练时可以按它过滤。
- `outcome` 全部来自 dco 的像素事实（`swipe`/`tap` 的 settle 结果）和文字识别读到的数字，**不信老师自己说有没有效**。
- `label`：`effective`（画面有变化且没有退回）、`noop`（没变）、`harmful`（碰到了价格、购买、提示、重新开始这类字，或弹出了要钱的画面）、`unknown`。
- `rationale` 可有可无，一句话，给以后训练「先想再点」用。
- 只记**确认是游戏画面**的步（隐私闸没有拦、dct 的画面鉴定不是私人内容）。

## 老师怎么教（四件事）

1. **示范：** 老师在新游戏里从头玩一段，成功的步标 `effective`。
2. **解释：** 每个关键点一句话说明为什么点这里（`rationale`）。
3. **纠正：** 小模型玩时，每步先让它给出点哪里和一个自信度；自信度低、或点完 `noop`/`harmful`，就问老师「这里该点哪」，把老师的答案记为一条 `teacher` 的 `effective` 训练数据，小模型原来的错误记为反面例子。
4. **由浅入深：** 先教菜单、对话框、固定按钮（最容易），再教场景里的大物件，最后才是小物件和小游戏。每一级过关率达到约定值（先定 80%）再进下一级。

## 训练

- 底座 `mlx-community/Qwen3-VL-4B-Instruct-4bit`，用 `mlx_vlm.lora`（Mac 2 的 `dc-octo/experiments/fast-decision/vision/train_lora.sh` 是现成的脚本和参数：rank 8，alpha 16，学习率 1e-4，视觉塔冻结）。
- 输入：缩小后的截图 + 文字识别出的字；输出：一小段 JSON，`{"x_bp": …, "y_bp": …, "why": "…"}`。**点击位置用整数万分比**，和 dco 的 `tap_at` 参数一致。
- 只用 `effective` 的步做正例；`noop` 和 `harmful` 做反面例子（单独的负样本损失，或者先不用，第一版只用正例）。
- 数据划分：整关留出来做验证，**不能在同一关的画面上同时训练和验证**。
- 每次训练产出一个版本号的补丁（`~/.dct/learn/<游戏名>/adapters/v0001/`），**训练失败或评估变差就丢掉，不覆盖当前在用的补丁**。
- 训练在本机后台跑，用户看不到任何术语，只看到章鱼说「在学习」。

## 评估

留出的关卡上让小模型玩，指标：
- **命中率：** 点出去后画面有变化（`effective`）的比例；
- **有害率：** `harmful` 的比例，**必须是 0** 才能上线；
- **相对老师：** 同样的画面，老师的命中率是多少。

小模型的命中率没有超过「不加补丁的底座」之前，不启用补丁。

## 老师是谁、条款

- **Claude 来教：** 用户要求。当下可以由对话里的 Claude 手动当老师（慢、贵，只用于攒第一批数据）；以后 dct 要自己调 Claude，需要在 llm 层加图片通道，并且每次开玩前用户同意一次，只发确认是游戏画面的图。
- **千问当老师：** 网关里的千问 3.8（已验证读大按钮和大物件的位置准），便宜，随时可用。
- **用户示范：** 最可靠。
- 用 Claude 的输出训练模型是否被条款允许，**由用户核对后决定**；没确认之前，训练只用 `qwen` 和 `user` 的数据。每条记录都有 `teacher`，所以这是个随时可以切换的过滤条件，不影响现在做记录。


## 大模型解决问题的过程，就是教会四样东西的过程（用户 2026-10-04 的总结）

每一次大模型（Claude）在一个游戏里把一个卡点解决掉，**都要同时产出四份东西**，不只是训练数据：

| 教给谁 | 产出什么 | 例子（《Darkness and Flame》） |
|---|---|---|
| **本地小模型** | 一条带结果标签的训练记录（上面的格式） | 「场景里的箱子在 (0.18, 0.62)，点它，画面变了」 |
| **dcv（知识和规矩）** | 一份草稿，由用户确认才生效：画面地图、可点区域、要避开的按钮、这个游戏怎么玩的笔记 | 「主菜单→主线/额外章节选择框→场景；提示和『+』要花钱，不点；场景中间可点」 |
| **dco（章鱼的能力）** | 一条能力缺口的请求，发给 dc-octo | 「没有按坐标点的工具」「划完要知道画面变没变」「隐私闸」，今天已经各发了一条 |
| **dc.ai（菜单栏里给用户看的）** | 一条待确认项或一句说明 | 「等你确认：游戏《Darkness and Flame》的可点区域」 |

做法是：**把「我卡住了，怎么解决的」当成一个对象记下来**（卡点是什么、大模型怎么解决的、用了哪份规矩或哪个新能力），再由 dct 分发给这四处。已经被解决过的卡点，下次遇到应该由小模型、dcv 的资料和 dco 的能力直接处理，不再需要大模型。

这样「让大模型教会本地小模型」和「让整个系统越用越懂」是同一件事：大模型是老师，也是整个系统的学习入口。

### 在基础设施没好之前，怎么继续玩

点击权限和 `tap_at` 做好之前，dco 不能按坐标点场景。这段时间可以用「合作模式」：
- **大模型看，用户点：** Claude 看着画面，说「点这个箱子」，用户在 iPhone 镜像里自己点；dct 用文字识别和画面前后变化记下每一步，当作示范数据（`teacher: user`，动作位置用大模型描述的物件加上用户点的结果）。
- 带字的按钮（PLAY、OK 之类）dco 现在就可以点，不需要等。

## 前提（都还没有）

1. **点击权限：** 放行凭据 + `tap_at`（dct-brain 的票格式和 dco 都要改，设计在另一份文档，需要用户确认）；
2. **图片通道：** dct 的 llm 层现在不能带图；
3. **记录写入：** `play()`/新的 `scene` 循环里把上面的记录写出来；
4. **画面鉴定要能区分「游戏画面」和「私人画面」**（已有 dco 隐私闸和 `dct game identify`）。

## 分几步做

1. 记录格式 + 写入（含图片，本机目录，大小限制，可清理）。
2. 点击权限（放行凭据、`tap_at`）。
3. 场景循环 `dct game scene`：截图 → 老师/小模型选点 → 用 `tap_at` 点 → 用 settle 判断有没有变 → 记录。
4. 训练脚本包装（`dct game train`）和评估。
5. 纠正循环（小模型玩、低自信度就问老师）。

每一步都是独立的小功能，各自有设计、计划和测试。

## 不做（这一轮）

- 每个用户一个专属补丁（见 `dct-learning-and-training-direction` 记忆：先做知识个性化，再做共享模型，最后才是个人补丁）；
- 给小模型加强化学习的奖励训练；
- 在云端训练或把数据上传去训练。

## 已知的风险

- **小物件**（散落的小石子、小宝石）靠 4B 小模型可能很难点准；千问读大物件位置偏差在 5% 以内，小物件没测。
- **数据量：** 点击位置这类任务，可能要几千条有效例子；先从菜单和大按钮练起，看学习曲线再估。
- **游戏更新或换皮肤**会让旧补丁变差；每个游戏有版本号，换了就重新评估。
- **有害操作必须是零：** 即使小模型选了价格或购买位置，dco 的票和 OCR 落点检查还是会拒绝；这道门不依赖模型。
