# dct 的 LLM 连接层 + 出错解释 + 例行问题自答 —— 设计

**状态：** 设计已确认，未实现
**总纲：** `2026-08-06-dct-supervisor-vision.md`（五件事里的第 1、2、3 件）
**前置：** `2026-08-05-dct-agent-error-detection-design.md`（`error_pattern` 与 `Failed` 态已实现）

## 问题

dct 没有任何 LLM 能力。要做总纲里那五件事，先得有一条 dct 自己能用的模型连接。

用户对这条连接提了两个要求：

1. **覆盖所有主流模型**
2. **认证要同时支持 API Key 和 SSO**

## 范围

**要做：**

- 连接层：后端、凭据、供应商登记表、配置
- 出错解释（第 2 件事）：会话进 `Failed` 时说人话
- 例行问题自答（第 3 件事）+ 它的必要前置：渠道（第 1 件事）

**不做：**

- **不做偏好学习。** 本轮的「记住用户怎么答」是**日志 + 每项目显式规则**，
  可读可改可删。从历史里推断偏好留给第 5 件事的 spec——先给用户一份看得见的
  规则表，好过让模型悄悄对他形成看法。
- **不做摘要**（第 4 件事）。
- **不建 webhook 基础设施。** 飞书/企业微信/钉钉/短信/WhatsApp 只留可加的位置，
  不半做。微信个人号做不了，见总纲。

## 架构

三层，都在 `src/llm/` 下，都不碰 TUI 重绘循环。

### 第一层：后端

一个 trait，两个实现，传输层注入——沿用 `verify.rs` 里 `verify_with` 已有的套路，
这样 401 / 超时 / 输出畸形都能不打网络地测。

```rust
trait Backend {
    fn complete(&self, p: &Prompt) -> Result<String>;
}
```

- **`CliBackend`** —— 把某个 profile 用无界面方式拉起来，读 stdout。
  已实测存在的无界面模式：`claude -p/--print`、`codex exec`。
  **认证是那个 CLI 自己的事，dct 什么都不传。**
- **`HttpBackend`** —— `ureq` POST 到 OpenAI 兼容或 Anthropic 兼容端点。
  阻塞式，跑在工作线程上，与「不引入 async 运行时」一致。

### 第二层：凭据

**和后端分开**，因为同一个后端可以配不同来源的凭据。

```rust
enum Credential { Inherit, Key(String), Bearer(String) }
```

- **`Inherit`** —— 什么都不用解析，`CliBackend` 直接拉起，CLI 自己认证。
  **用户要的 SSO 在这里是零代码的。**
- **`Key`** —— 从现有 `SecretStore`（`~/.dct/secrets.toml`）读。**不新建第二个密钥存储。**
- **`Bearer`** —— 从 CLI 已存的 OAuth 里取。本机实测：

  | CLI | 位置 | 形状 |
  |---|---|---|
  | Claude Code (macOS) | Keychain，service = `Claude Code-credentials` | `claudeAiOauth.accessToken` / `.refreshToken` |
  | Claude Code (Linux) | `~/.claude/.credentials.json` | 同上 |
  | Codex | `~/.codex/auth.json`（0600） | `tokens.access_token` / `.refresh_token` / `.account_id`；另有 `auth_mode` 和 `OPENAI_API_KEY`（本机为 `null`，即这台机器是 SSO 登录而非填的 key） |

  `auth_mode` 这个字段本身就告诉 dct 该走 `Bearer` 还是 `Key`，不用猜。

**提取在类型上就是可失败的**：返回 `Option`，不返回会往上冒的 `Error`。
字段缺失、形状对不上、格式变了，一律得到 `None` 加一条警告，然后落到下一个
声明的来源。

> 这是对「厂商格式没有文档、说变就变」这个风险的收容手段。厂商一升级，
> 用户退化成「填个 key」，**不是 dct 坏掉**。

### 第三层：供应商登记表

**登记表长在 `profiles/*.toml` 上，不另起一份平行的清单。**

profile 新增两个可选块：

```toml
[headless]
# 怎么无界面地跑它
command = ["claude", "-p"]

[api]
base_url = "https://api.moonshot.cn/anthropic"
wire = "anthropic"   # 或 "openai"
```

> 「HTTP 客户端 + 自己解析凭据」那条路真正的代价从来不是 HTTP 客户端，
> 而是**要在已有的九个 profile 之外再维护一份供应商清单**，从此两份清单
> 要永远保持同步。长在 profile 上就只有一份。

于是「覆盖所有主流模型」= **加 profile**。那已经是一个有文档的、用户自己
就能扩展的文件格式（`~/.dct/profiles/*.toml`），不是一个新子系统。

### 配置

`~/.dct/config.toml` 新增 `[llm]`：provider、model、可选的 base_url 覆盖。
整段缺失 = 默认用 `claude` profile 的无界面模式——那是用户最可能已经登录过的 CLI。

## 数据流：自答流水线

```
tick → SessionState::Asking（已有的正则机器，src/session.rs:26）
     → 抓当前画面（已有的 scrollback）
     → 工作线程，绝不在重绘循环里
     → 抽出问题和选项
     → 关键词规则判「重要」——不调模型
     → 重要        → 经渠道发给用户，等他回
     → 例行 + 有把握 → 敲进 PTY，记账
     → 例行 + 没把握 → 也发给用户
     → 每一个决定都写进 journal（src/journal.rs）
```

第 1 件事和第 3 件事就是这一条流水线的两个出口。

## 渠道

可插拔 trait。**默认「只在终端里」**——没有渠道就不许自动回答。

本轮实现两个适配器：

- **Telegram** —— `getUpdates` 长轮询，NAT 后面的笔记本不需要服务器和公网域名。
  只接受用户本人的 chat id。出站消息必须经得起被念出来：一句话、自足、
  无路径、无 diff、无代码块；选项**同时编号和带标签**，因为口述回复是
  「就第二个吧」而不是 `2`。
- **macOS 通知** —— 点回 dct。

其余渠道的前置条件写在总纲的表里，本轮不建。

## 自答的安全姿态

这一节是本轮唯一能真正伤到用户的地方。

- **默认关闭**，按项目显式打开。
- **关键词规则在任何模型调用之前跑**，模型改不了它的判定。
- 钱、部署、force push、删除、动项目目录外的东西 → 一律升级，不看把握。
- 「选哪种方案」→ 升级。「先做哪个」→ 才算例行。
- 历史里没有先例 → 升级。
- **不设超时自动选默认项。**
- 每一个自答都记账、可撤销。

### 「有把握」是什么意思

**不是模型给的置信分。** 模型对自己有多确信这件事，本身就不可靠，
拿它当安全阀等于把安全决定交给模型。

本轮的定义是**有没有先例**：journal 里存在一条同类问题、且用户当时的答法一致。
没有先例 = 没把握 = 升级。

于是第一次遇到某类问题**一定**会问用户，第二次开始才可能自答——用户实际看到的
是「它记住了我上次怎么说」，而不是「它猜我想要什么」。这也是本轮把偏好学习
限定成日志加显式规则的原因：先例是查出来的，不是推断出来的。

## 错误处理

统辖规则：每一处 LLM 用法都有不依赖 LLM 的退路，退化方向永远是
「dct 变回今天的样子」。

| 出什么事 | dct 怎么办 |
|---|---|
| 后端连不上 | 功能安静下线，会话照跑 |
| 凭据提取失败 | 落到下一个来源，最终是「请填一个 key」 |
| 模型输出畸形 | 当作**没把握**，升级给用户 |
| 模型慢 | 工作线程 + 硬超时，看板全程照常重绘 |

**卡住的 TUI 是用户最恨的失败模式**——一个冻住的 dct 和一个死掉的 agent
在屏幕上长得一模一样。

## 测试

- 后端与渠道都在 trait 后面、传输层注入：401 / 超时 / 输出畸形全覆盖，零网络。
- 凭据提取：对**录下来的**凭据形状做表驱动测试。**测试永远不读真实 Keychain。**
- 「重要」分类器有专门语料，包含：
  - 用户截图里那句「先跑完还是现在改」，标注为**例行**
  - 一组危险措辞，**必须全部升级**

  这是唯一真会伤到用户的东西的回归套。

## 实测验证

用户要求「配置写完还要真打端点验过」。**下面是 2026-08-06 真跑出来的结果**，
没跑过的一律记成「未验证」，不当作跑过。

### 跑通了的

| 项 | 结果 |
|---|---|
| 关着的时候真的是关的 | ✅ 没有 `[llm]` 段时打印「功能现在是关着的」并退 1，不建任何后端 |
| `claude -p` 走已有 SSO | ✅ **通了**，模型答「好」，9.4 秒。全程没有任何 key，认证完全靠 Keychain 里已有的登录 |
| `codex exec` 走已有 SSO | ✅ **通了**，模型答「好」，认证靠 `~/.codex/auth.json` |
| 四条拒绝路径的措辞 | ✅ opencode（没无界面模式）/ 不认识的名字 / claude 直连（没 `[api]`）/ kimi 没密钥，四句都是人话、都给得出下一步、都退 1 |
| **凭据不会跑到别人家去** | ✅ kimi + 直连 + 没填密钥 → 说「还没有密钥，按 c 填」，**不会**去摸 Keychain 里的 Anthropic token。这是那个 Critical 在运行时的验证，不只是单测 |
| HTTP 传输层（`send_real`） | ✅ 对着本地一个假 Anthropic 端点跑通，并**核对了真正发出去的报文**：路径 `/v1/messages`、`system` 在**顶层**而不是塞在 `messages` 里、model 来自配置、`x-api-key` 与 `authorization` 都在 |

`send_real` 与 `run_real` 是全计划里仅有的两个没有单测的函数，也正是各自藏过一个
bug 的地方。这一轮两个都真跑过了。
