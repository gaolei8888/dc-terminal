# dc-terminal 设计

日期：2026-08-01
状态：已确认，待写实施计划

## 目标

一个面向 vibe coding 的 agent 终端。核心目的：**开了任务之后，人可以离开电脑，在手机上继续操控。**

面向开发者本人和同行，不受 `dc_classroom` 那套「不出现术语」的约束。

## 不做什么

- 不做终端模拟器（不替代 iTerm / Ghostty）
- 不在智能眼镜上跑 UI；眼镜通过手机的消息通知和语音回复间接接入，不做专门集成
- 不做权限确认，任何情况都不问
- 会话不中途切目录

## 核心模型

**Session** —— 一个 agent 进程 + 它的 PTY + 一个 git worktree。状态四个：`Working`、`Asking`、`Idle`、`Stopped`。

**Profile** —— 一个 TOML：启动命令、自动接受参数、判断 idle 的正则。内置 Claude Code、Codex、普通 shell 三个。加新 agent 写 TOML，不改代码。

**Bridge** —— 本地小服务，绑 `127.0.0.1` + token 校验。只提供 `ask_human` 一个工具：agent 调用即阻塞，问题送到手机，回复作为返回值。

**Relay** —— 把 `Question` 发到通道、把 `Answer` 收回来。只认这两个结构，不依赖会话内部实现。

## 进程结构

`dct` 是常驻守护进程，持有所有会话。TUI 和手机是它地位平等的两个客户端。直接敲 `dct` 把 TUI 接上去，没在跑就顺手拉起。

关掉终端窗口不影响会话——这是「人走了还能操控」的前提。

## 自动接受

所有 agent 用各自的绕过参数启动（`claude --dangerously-skip-permissions`、`codex --full-auto`），全程不问权限。

安全性不靠拦截，靠事后可恢复：

- 每轮开始前在该会话的 worktree 里自动提交检查点
- `/undo` reset 回上一个检查点
- `/stop` 杀掉进程

## 手机端

**只有一套消息格式。** 出站永远是「一句话 + 可选的编号带标签选项」；入站永远是自由文本，由 `dc_llm`（`:8700`）归类成选项或当作指令原文。开新任务选项目、选 agent 用的是同一套格式，没有第二套交互设计。

这套格式的约束来自语音场景（眼镜念出来、口述回复）：

- 出站问题必须自足，无文件路径、无 diff、无代码块，不引用「上面第 3 项」
- 选项同时编号和带标签，因为口述给出的是「就第二个吧」而不是 `2`
- 路由隐式，靠通道的回复引用承载；SMS 无法承载，需在消息里带会话标签
- 压不到一句话的问题，发简短摘要加「去看板处理」

**一个会话 = 手机上一个聊天话题。** 在话题里说话，内容直接进 agent。

命令：

| 命令 | 作用 |
|---|---|
| `/new` | 依次问目录、agent、第一句 prompt，每步编号选项 |
| `/list` | 所有会话和状态 |
| `/diff` | 改了哪些文件、各自 +N/-M，不发完整 diff |
| `/undo` | 回滚到上一个检查点 |
| `/stop` | 杀掉该会话 |

## 通道与备用通道

适配器四个：Telegram、飞书、企业微信、SMS。Telegram 排第一，因为它是唯一不需要公网回调地址的。

**通道配置成有序列表，主通道 + 一个或多个备用通道，用户预先指定。** 发送报错或超时即判失败，自动切下一个通道重发，消息里标明主通道不可用。

不能在故障时问用户选哪个——问这件事本身就要靠通道。所以备用通道必须提前定好。

会话粘在实际生效的通道上：用户从哪个通道回复，这个会话后续就走哪个，不来回跳。

SMS 适合放在最后一位，它不依赖任何 app 和额外网络。

（通道需要配 token 和 chat id；前面「没有配置文件」只针对目录。）

## 目录规则

没有配置文件，没有白名单。

- TUI：`dct` 在哪个目录启动，新会话默认用那个目录
- 手机：`/new` 之后直接发路径；编号列表只是「最近用过的」快捷方式
- agent 会话绑定一个目录直到结束——检查点和 `/undo` 成立的前提
- shell pane 不受约束，`cd` 随意，因为它没有 worktree 和检查点

换目录就是开新会话。

## 数据流

`/new` → 选目录、选 profile、给第一句 prompt → 建 worktree 和分支 → 按 profile 拉起 agent，环境变量带 bridge 地址和 token → agent 开跑，不问权限 → 每轮前自动提交检查点 → agent 调 `ask_human`，调用阻塞 → 问题经 `dc_llm` 压成一句话加选项，发到该话题 → 用户回复 → `dc_llm` 归类 → 作为工具返回值给 agent → 继续。

正则判定 `Idle` 时往话题发通知。`/diff`、`/undo`、`/stop` 直接作用在该 worktree 和进程上。

## 失败处理

- **`dc_llm` 挂了** —— 问题原样转发，回复只认编号。降级不中断。
- **主通道挂了** —— 自动切备用通道重发，标明主通道不可用。
- **所有通道都挂了** —— 消息排队重试，会话停在 `Asking`，TUI 上标红。**永远不替用户回答，不设超时自动选默认项。**
- **agent 不调 `ask_human`，直接在屏幕上问** —— 正则判成 `Idle` 并通知；用户直接发文字进去。这是通用 CLI 的正常路径，不是异常。
- **worktree 建不了**（非 git 仓库、分支冲突）—— 拒绝开会话并说清原因，不悄悄退化成在主工作树里跑。
- **回复归类不确定** —— 回「没听清，回数字」，不猜。
- **守护进程重启** —— 会话进程随之结束，重启后不自动恢复，只列出遗留 worktree 让用户决定。

## 安全

两条都不是可选的：

1. bridge 只绑 `127.0.0.1`，校验 token
2. bot 只接受用户本人 chat id 的消息——bot 能开会话、能发指令，谁摸到 bot 谁就能操控这台机器

## 技术选型

Rust + ratatui，单二进制。PTY 用 `portable-pty`，屏幕解析用 `vt100`。

代码一个 crate，按模块分：`session`、`pty`、`bridge`、`relay`、`git`、`ui`。

## 实施顺序

不是砍范围，是先后。全链路打通比铺开更重要：

1. 守护进程 + TUI + PTY + worktree 检查点，profile 只做 Claude Code 和 shell
2. bridge 的 `ask_human` + Telegram 通道 + `dc_llm` 压缩与归类，跑通「手机收到问题、回复进会话」
3. `/new`、`/diff`、`/undo`、`/stop`、`/list` 全套手机操控
4. 加第二个通道，打通备用切换；再补齐剩余通道和 Codex profile

## 测试

- 录真实 Claude Code / Codex 输出当 fixture，测 idle 正则
- relay 用假通道 + 假 LLM，测消息契约：一句话、无代码块、选项编号带标签
- git 用临时仓库测检查点和 `/undo`
- TUI 用 ratatui `TestBackend` 做快照
