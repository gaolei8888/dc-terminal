# dct 看板双模式 —— 设计

**状态：** 已实现，待 review
**位置：** 换项目重做五步（D → A → B → C → E）的第三步
**依赖：** D（`App::visible`）已完成——两个模式必须看到同一批会话，否则切模式会话数会变

## 问题

看板只有列表一种画法。九宫格（`grid.rs`）虽然是个完整视图，但它是**列表的一个附属页面**：

- 启动永远落在列表（`app.rs` 的 `view: View::Board`）
- 所有「回看板」的落点（退出会话、换完项目、存完密钥、会话结束……）**一律硬编码回列表**，
  哪怕用户刚才一直在九宫格里
- `Ctrl+Q` 在九宫格里退回列表，等于说「九宫格是列表的下一层」
- **`g` 在九宫格里能用，但帮助行里没写**——这个仓库反复警惕的「屏幕上没写却真管用的键」，
  这次犯在自己身上

用户的原话是「有列表模式和九宫格模式」。两个**模式**，不是一个视图加一个附属页面。

## 范围

**要做：** 两个模式平级；`g` 切换并记住选择；所有「回家」的落点都回到用户选的那个模式；
九宫格帮助行补上 `g`。

**不做：**

- **不改九宫格自身的渲染**（格子布局、翻页、配色一律不动）。
- **不做窗口过小时自动降级到列表。** 九宫格现在会说「窗口太小，放大终端窗口后再看九宫格」，
  那是一句用户自己能照做的话。悄悄换成列表反而让他不知道自己看的是哪个模式，
  也不知道为什么。
- **不动作用域（`a`）。** 它已经是跨模式共享的，本来就对。

## 架构

```rust
/// 看板的两种画法。它们是**平级**的，不是「列表 + 一个附属页面」。
pub enum ViewMode { List, Grid }
```

存在 `settings.json` 里，跟语言并排（`settings::load_view_mode` / `save_view_mode`）。

**新装默认是九宫格。** 列表在宽屏上是一屏留白，而九宫格直接给出每个会话在干什么——
后者才是「一屏管好几个 agent」这件事的样子。用户存过选择之后，存的那个说了算。

### 「回家」只有一个落点

```rust
/// 用户选的那个模式对应的视图。**所有「回看板」的地方都必须走这里。**
fn home_view(app: &App) -> View
```

原来有 12 处硬编码 `View::Board`。留着任何一处，用户就会在某条路径上被莫名其妙地
甩回列表——而且是那种「偶尔发生、复现不了」的观感 bug。

`home_view` 同时负责让两个模式对「当前是哪个会话」的认知一致：进九宫格时焦点落在
列表光标那一行，回列表时光标落在焦点格上（复用已有的 `sync_board_cursor_from_grid`）。

### 两个模式都是顶层

| | 改之前 | 改之后 |
|---|---|---|
| `q` | 列表退出 dct；九宫格也退出 | 不变，两边都退出 |
| `Ctrl+Q` | 九宫格 → 列表 | **两边都无动作**（已经在顶层了） |
| `escape_hint` | 列表 `q 退出`；九宫格 `Ctrl+Q 回列表` | 两边都是 `q 退出` |
| `g` | 互相切换，但九宫格的帮助行没写 | 互相切换，**两边帮助行都写出来** |

`back_one_level(Grid)` 从 `Some(Board)` 改成 `None`：九宫格不再是列表的下一层。
留着的话 `Ctrl+Q` 会变成 `g` 的一个隐藏同义词，而屏幕上说的是「回列表」——
用户会以为自己退出了什么。

## 测试

1. `g` 在两个方向上都切换模式，并且**落盘**
2. 重新构造 `App` 时读回存过的模式
3. 没存过 → 九宫格（新装默认）
4. 存的值坏了 / 不认识 → 退化成默认，不 panic
5. `home_view` 在列表模式下给 `Board`、九宫格模式下给 `Grid`
6. 从会话按 F2 回到的是**用户选的模式**，不是永远的列表
7. 换完项目回到的也是用户选的模式
8. `back_one_level(Grid)` 是 `None`（顶层）
9. `escape_hint` 在两个模式下都是 `q 退出`
10. 两个模式的帮助行里都写着 `g`，且说明是「切到另一个」
11. 切模式时光标/焦点对齐同一个会话（列表第 3 行 ↔ 第 3 格），两个方向都要
12. 空会话时切模式不 panic，焦点收拢到 0
