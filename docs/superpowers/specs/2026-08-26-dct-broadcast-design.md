# dct 直播：让一屋子人看着 agent 干活 —— 设计

**状态：** 探索。**不是一份可以照着实施的设计**——要不要做这件事本身还没有答案
（见最后一节）。下面写的是「如果做，会撞上什么、有哪些岔路口、每条路的代价是什么」，
**不是已经选好的路**。真要动手之前，这些岔路口得重新过一遍，那时候手上会多一样
现在没有的东西：一节课的真实反馈。
**起因：** 2026-08-26 用户问「做一个可以直播的版本有益处吗？因为我们要做这个疯狂AI训练营」。
**关联：**
- `2026-08-23-dc-terminal-srv-design.md` —— 直播是那个中转服务的**第一个真实用例**，
  而且比它原本那个用例（我想在手机上看自己的会话）硬得多。这份设计不重复那边的
  决定，只写直播多出来的部分。
- `2026-08-23-dct-phone-lan-phase0.md` —— **观众页面已经做完了**，那就是手机端那一页；
  直播要做的是把它从"一个观众，就是机器主人"改成"很多观众，都不是机器主人"。

---

## 问题

疯狂AI训练营的课就是「**AI 在干活，老师在讲清楚为什么**」——每周 90 分钟，学员当场提需求，
agent 现场开发，老师同步讲解，看着一个项目从简陋长到可用（`ai-mania` 站上那句
「你提需求，AI 现场开发」和「双轨制：项目实践轨 / 内容讲解轨」写的就是这件事）。

今天这件事靠屏幕共享。屏幕共享能用，但它把一堂**关于终端的课**压成了一路视频，于是：

- **手机上读不清。** 一屏 120 列的终端压进 1080p 再缩进手机，是一团糊。而学员里
  相当一部分只有手机。
- **只能看一个窗口。** 「双轨制」的意思是老师在讲的同时有好几个 agent 在跑，
  而屏幕共享一次只能给一路——**学员没法自己选看哪一个**。
- **抄不走。** 老师刚敲的那条命令，学员只能照着视频重打一遍，然后打错。
- **回放贵。** 90 分钟视频几个 G，而学员最常问的是「刚才那句是什么」——
  他们要的是往回翻几屏，不是倒带。

`dct` 手里有的东西正好补这几样：屏幕不是像素，是**结构化的文字**
（`Response::Screen` 里那些 `ScreenSpan`）。

---

## 为什么值得做

四条，全都是**视频做不到**而不是"也能做到"：

1. **传文字不传像素。** 一路终端一秒钟几 KB，一百个观众照样撑得住；同样人数的
   1080p 屏幕共享是另一个量级的账单。手机上也真的读得清——字是字，不是被压过两次的
   一团。
2. **同时看好几路，而且各看各的。** 老师在讲解轨说话时，实践轨上三个 agent 在跑，
   **每个学员自己选看哪一个**。这一条视频在原理上就做不到。
3. **文字能选中、能复制。** 命令、报错、路径，学员直接抄走。
4. **回放便宜到可以默认打开。** 存的是帧不是视频，一节课几百 KB。
   「刚才那句是什么」变成往回翻两屏，而不是拖进度条。

## 岔路口一：只读怎么保证——一个开关，还是路由压根不存在

观众永远不能往老师的终端里敲任何东西。落实的方式**不是加一个 `read_only: bool`
然后到处判**，而是：

一条路是加一个 `read_only: bool` 到处判；另一条是**广播那一路根本不注册写的那几条
路由**。

现在的路由层（`src/web/routes.rs`）里，读（`/api/sessions`、`/api/screen`）和写
（`/api/input`、`/api/key`、`/api/scroll`）本来就是分开注册的。广播模式给观众的是
一份**只挂了读路由**的 `Routes`——写的那几条在那个进程里**不存在**，不是"存在但被
拦住"。

我倾向后者，理由不在今天而在半年后：一个布尔值意味着每加一条新路由都要有人记得
判一次它，而漏判的那一次不会有任何东西报错，只会有一个学员发现自己能往老师的终端里
打字。仓库里已经有一处同形状的做法可以抄——`daemon::handle` 那个
`web: Option<…>` 参数，安全边界长成"物理上拿不到"而不是"记得检查"。

代价也得摆出来：拆成两套 `Routes` 之后，将来某个既要读又要写的场景（比如助教能替
学员敲一句）会比加个布尔值麻烦。真遇到那天再说，不必现在为它让路。

---

## 事实一：直播不可能是局域网的，这是它的价格

手机端那一版之所以能不碰服务器，全靠"观众就是机器主人、而且在同一个 WiFi 下"。
直播两条都不成立：观众是几十个不在你网络里的人。

**所以直播 = 必须先有 `dc-terminal-srv`。** 那份设计里所有的代价原样成立：公网入口、
ICP 备案、以及从此为经过你服务器的内容负的责任。

但反过来说：**直播是那台服务器真正的理由。** "我想在手机上看自己的会话"是个便利，
砍掉不心疼；"老师给一屋子学员上课"是产品本身。而且身份那一块正好是现成的——
观众本来就是 dc_classroom 上注册的学员，跟那份设计里"只服务注册用户"是同一句话。

---

## 事实二：泄漏风险比自己看手机高一个量级

老师的终端上会出现：文件路径、往 agent 里粘的 API key、agent 顺手 `cat` 出来的
`.env`、仓库里的客户数据。屏幕共享至少老师自己看得见在共享什么、能立刻停；
**一个常开的直播是一次误操作直接进全班的眼睛，而且已经进了。**

三件事看起来躲不掉，但具体怎么做值得到时候再定：

1. **播哪几个会话，恐怕得是逐个点名的**，而不是"把我所有会话都播出去"——老师同时
   开着的另外那个会话里可能是完全不相干的活。（也可能实际上课时老师就想全播，
   那就另说。）
2. **"正在直播"得在屏幕上，而且挤不掉。** 底栏那个反白牌子的做法可以直接抄
   （`ui::mod.rs` 里当前项目那一块）——它是那一屏唯一一处反色。跟"哪几个在播"
   写在一起比一个笼统的红点有用。
3. **暂停键要让观众知道是暂停了**，而不是留一屏冻住的旧画面——冻住的画面跟
   "网卡了"长得一模一样，而那一刻老师多半正在做他不想让人看的事。

---

## 岔路口二：观众从哪儿取帧

手机端那一版是"一个观众 300ms 拉一帧"。一百个观众照抄的话，就是老师那台笔记本
每秒被问三百次——而它还要同时跑着几个 agent。

一条出路是改成推：老师的 daemon 每 300ms 往 srv 推**一份**当前帧，srv 存住最新那
一份，观众从 srv 拿——老师那边的出网流量就跟观众人数无关了。这是我现在能想到的最
简单的形状，但它不是唯一的（SSE、WebSocket、观众之间分发都还没比过），真到那一步
再挑。

这跟端到端加密不冲突：**srv 存的是密文帧**，它照样看不懂。这正好用上那份设计里
预留的 `recipients`——一堂课一把房间密钥，老师的 daemon 用它加密，选课的学员拿得到。

## 一个便宜的起点：观众页面已经写好了

`src/web/page.html` 本来就是一个观众：会话列表、实时画面、断线提示、后台不轮询。
广播模式给它的差别只有两处：

- 输入区不出现（服务端也没有对应路由，见决定一）
- 多一行"这是谁的课、现在在播哪几个会话"

页面渲染那部分的测试原样搬过去还能不能绿，是"有没有被悄悄重写"的一个便宜检查
（第 1 期计划里也用了同一招）。

---

## 一个小考虑：老师需要知道多少

一个数字（"23 人在看"）大概就够，而且有用——对着空气讲和对着二十三个人讲是两回事。
"谁进来了/谁走了"的滚动名单我猜是负担：那是一条永远在动的东西，而老师正在讲课。
不过这条纯属猜测，真上课的人说了算。

---

## 现在看起来不该一起做的

- **声音和画面。** 老师的脸和话走现成的会议工具（腾讯会议/飞书）就好。终端是加在
  旁边的一块，不是替代品——光有终端不是一堂课。
- **观众反向输入。** 举手、提问、投票走课程平台自己那套。一旦观众能往终端里送东西，
  上面那条只读的路就要重新想一遍。
- **录制回放。** 它很便宜也很有价值，但**存下来的东西比直播更持久**——同一次泄漏，
  直播是当时在看的人看见了，回放是永远躺在那儿。等直播本身跑顺、老师对"我在播什么"
  有了肌肉记忆再说，不是不做。

---

## 如果真要做，大致的先后

1. **只读观众**：广播那一路只挂读路由；页面去掉输入区。
   **这一步不需要 srv**——先在局域网里让同屋子的人扫码看，教室里就够用了。
   （如果验证下来只需要"教室里能看"，那后面几步可能永远不用做。）
2. **上公网**：接 `dc-terminal-srv`（那份设计的第 1 期），身份走 dc_classroom，
   一堂课一个房间。
3. **推帧与扇出**：daemon 推一份、srv 存最新一份、观众从 srv 取（决定四）。
4. **加密**：房间密钥 + `recipients`（srv 设计的第 2 期）。
5. **回放**：等前面都稳了再说（见「不做什么」最后一条）。

---

## 先验证什么

**别从第 1 期开始写代码。下一节课先用现在这一版试一次**：手机端已经能用了，
在教室里把它投出来，或者让到场的学员扫码看。

要的答案只有一个：**学员到底会不会去看终端。**

- 他们真的会盯着看、会往回翻、会抄命令 → 这份设计有了被验证过的理由，而且第 1 期
  是现成的（页面已经写好，只是少注册几条路由）。
- 他们只想看老师讲、看最后跑起来的结果 → **整摊都不用做**，省下的是一台服务器、
  一次备案，以及从此为经过它的每一屏内容负的责任。

这跟第 0 期计划最后那条验收条件是同一句话：**这一期真正的产出不是代码，是一个答案。**
