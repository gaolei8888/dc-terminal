# dct 选项目重做 —— 设计

**状态：** 已实现，待 review
**位置：** 换项目重做五步（D → A → B → C → E）的第四步
**取代：** `2026-08-03-dct-project-switch-design.md` 里选择器那一部分

## 问题

用户对上一版选择器的评价是「完全是混乱的」，并明确要一个**目录浏览器**。现状：

- **全屏接管。** `mod.rs::draw` 按 `View` 单选一个渲染器，按 `p` 的那一刻看板/九宫格
  整个消失，屏幕上只剩一个几乎全空的框（用户截图里就是这样）。
- **只能靠记忆和打字。** 列表里只有「最近开过会话的目录」。没开过的项目要么打字过滤
  （过滤的是已有列表，找不到就是找不到），要么走「手输路径…」把完整路径敲一遍。
- 一个没在列表里的新项目，实际上**没有办法浏览着找到它**。

## 范围

**要做：** 居中浮层；左右分栏（左「最近」，右「目录浏览器」）；`Tab` 切焦点；
`→` 进目录 / `←` 上级 / `Enter` 选定；标出哪些目录是 git 仓库。

**不做：**

- **不做文件浏览，只列目录。** 选的是项目，文件是噪音。
- **不在这里判 git 仓库能不能开 agent。** `session.rs` 已经在建会话时判了；
  这里只**标出来**，让用户在选之前就看得见，不重复一套判断。
- **不做新建目录 / 重命名。** 选择器就是选择器。

## 架构

### 视图状态收成一个结构体

`View::PickProject` 原来有 4 个平铺字段，现在要 8 个。继续平铺下去，每次
`match` 解构都要抄一长串，加字段就得改遍所有分支。收成一个结构体：

```rust
pub struct ProjectPicker {
    recent: Vec<String>,        // 守护进程给的，过滤不改它
    recent_state: ListState,
    cwd: PathBuf,               // 浏览器现在在哪个目录
    entries: Vec<DirRow>,       // cwd 下的子目录
    browse_state: ListState,
    focus: Pane,                // Recent | Browse
    filter: String,             // 只作用于**当前焦点那一栏**
    typing_path: Option<String>,
}

struct DirRow { name: String, is_git: bool }
enum Pane { Recent, Browse }
```

### 浮层

`draw()` 先照常画当前的家视图（列表或九宫格），再在中间盖一层：

```rust
// 宽高各取「终端的一大半」和一个上限的较小者，然后居中
let w = area.width.saturating_mul(4) / 5).min(100);
let h = (area.height.saturating_mul(3) / 4).min(24);
```

盖之前先 `Clear`，否则背后的格子会从边框缝里透出来。**背后留着看板**是重点：
用户要看得出自己只是叠了一层，Esc 一下就回去了——这正是上一版被判为「混乱」的一部分。

终端太小放不下浮层时**退化成全屏**，不是显示一句「窗口太小」：选项目是用户此刻
非做不可的事，挡住他没有意义（跟九宫格不同——那一屏本来就是「看一眼」，看不了
就先别看）。

### 两栏

| | 左：最近 | 右：浏览 `<cwd>` |
|---|---|---|
| 内容 | 守护进程给的最近项目，末行是「手输路径…」 | `cwd` 下的子目录，git 仓库标出来 |
| `↑↓` | 移动 | 移动 |
| `Enter` | 选定这个项目 | **选定这个目录**（不是进入） |
| `→` | 把浏览器切到这个项目所在目录 | 进入这个目录 |
| `←` | —— | 上一级 |
| 打字 | 过滤本栏 | 过滤本栏 |

`Enter` 在右栏是「选定」而不是「进入」是刻意的：用户走到一个目录上，多半是因为
**它就是**他要的项目，而不是想再往下钻。想往下钻有 `→`，那是个方向键，语义天然
就是「往里走」。反过来设计（Enter 进入、别的键选定）会让「选中我现在看着的这个」
需要一个学过才知道的键。

**过滤只作用于当前焦点那一栏。** 两栏共用一个过滤词的话，用户在左边打字找项目，
右边的目录列表会跟着变空，而他并没有要求那件事。

### 隐藏噪音

浏览器跳过 `.` 开头的目录，以及 `node_modules` / `target` / `build` / `dist` /
`.git`。理由见 `dc_classroom/CLAUDE.md` 的目标用户约束：构建产物和依赖目录不进
文件树。**跳过的东西不提示**——它们不是「被隐藏的内容」，而是本来就不该出现的噪音。

### git 仓库怎么判

**不调 `git::is_repo`**：那要 fork 一个 git 进程，一个目录几十个子目录就是几十次
fork。这里只 `stat` 一下 `<dir>/.git` 存不存在——判得没那么全（worktree、
`GIT_DIR` 都会漏），但这只是个**提示标记**，不是准入判断。真正的判断在
`session.rs` 建会话时，那里可以慢。

## 测试

1. 浮层不铺满：画完之后四角仍能看到背后的看板内容
2. 终端太小时退化成全屏，不 panic、不显示「窗口太小」
3. `Tab` 在两栏之间来回切，焦点有可见标记
4. 右栏 `→` 进入子目录，`cwd` 和列表都跟着变
5. 右栏 `←` 回上一级；已经在根目录时不动、不 panic
6. 右栏 `Enter` 选定**当前高亮的目录**（不是进入它）
7. 左栏 `Enter` 选定那个最近项目
8. 左栏 `→` 把浏览器切到那个项目所在的目录
9. 打字只过滤当前焦点那一栏，另一栏不受影响
10. `.` 开头的目录和 `node_modules` 不出现在列表里
11. git 仓库有标记，非 git 目录没有
12. 空目录（一个子目录都没有）不 panic，给一句话
13. 读不了的目录（权限）不 panic，给一句话
14. 选定之后 `current_dir` 变了、`visible` 重算了（复用 D 的 `switch_project`）
15. `Esc` 回到用户选的模式（复用 B 的 `home_view`）
