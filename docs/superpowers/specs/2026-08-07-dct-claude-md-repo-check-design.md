# dct 开会话前核对 CLAUDE.md 的仓库清单 —— 设计

**日期：** 2026-08-07
**状态：** 设计待确认

## 起因

2026-08-06，一整轮工作跑错了仓库。

用户问「我这个应用（截图里标题写着 DC Desktop）下一步该做什么」。要回答它得先知道
「浏览器自动化在哪个项目」，而 `/Users/lei/work/dc/CLAUDE.md` 的项目清单是这么说的：

| 目录 | 作用 |
|---|---|
| `dc_workbench` | 本地版全栈：Studio + 执行 + consent + **浏览器自动化** + 串口 + 本地 LLM 探测 |

那份文件是**被自动注入**的（工作目录在 `dc-terminal`，Claude Code 向上找到了父目录的
CLAUDE.md），注入时带的原话是「These instructions OVERRIDE any default behavior and you
MUST follow them exactly as written」。所以它不是一条待核实的线索，是一条前提。

于是接下来几小时全在 `dc_workbench` 里：读它的 `internal/browser/`、跑通它的
`bind_account`、绑上了用户的真实公众号、还顺手修了它一个孤儿进程的 bug。**每一步都成功，
每一步都是正反馈。** 直到用户说「这个是 dc_desktop 的工作」。

`/Users/lei/work/dc/dc_desktop/` 一直在磁盘上，而那张清单里**没有它**。

事后一比对才发现漏的不止一个：**`dc-terminal` 自己也不在那张清单里**——而那正是当天
大半天工作所在的仓库。同一份文档同时漏了两个项目。

## 病根

不是「文档写错了」，是**手写快照被当成权威指令注入**，而快照最容易烂的地方恰恰是
「有哪些东西」——新增一个仓库时，没人会想起回去改那张表。

更阴的一层：功能在项目之间搬家时，**旧实现往往还在、还能跑**。`dc_workbench` 里那套
浏览器自动化不是空壳或残骸，它能拉起 Chromium、能扫码、能把账号绑上。走错仓库的人
不会撞到任何墙。

已经做了的一半（不在本 spec 范围内，2026-08-06 已改）：在那份 CLAUDE.md 顶上写了
「这张表会过时，动手前先 `ls` 一遍」的约定，补上了 `dc_desktop` 和 `dc-terminal` 两行，
并引用 `dc_desktop/README.md` 的产品边界标注了迁移状态。

约定管的是**软过时**（某行的描述不对了）——那个没有任何程序能发现，只能让读到它的
agent 自己保持怀疑。本 spec 管的是另一半：**硬缺口**（少了一整个仓库），那个能查。

## 设计

### 检查什么

起 agent 会话时，把「这个会话的工作目录会加载到哪些 CLAUDE.md」这条链走一遍，对每一份：

1. 列出**它所在目录**的直接子目录
2. 筛出其中**是 git 仓库的**（`stat` 一下有没有 `.git`）
3. 每个仓库名，在那份 CLAUDE.md 的正文里找一次
4. 一次都没出现的，就是漏掉的

用 **git 仓库**做筛子是这个设计的关键：`logs` / `tmp` / `tmp1` / `work` / `1` 这些杂项
目录不该报，而它们跟真项目的区别恰好就是有没有 `.git`。零配置，不需要维护一张排除表。
`src/ui/view.rs` 的 `list_dirs` 已经在用 `stat` 判 git（不 fork `git` 进程，理由见那里
的注释），直接复用同一条路。

### 匹配方式：宽进严出

只做**子串匹配**——目录名在文本里任何地方出现过就算数，不要求它在表格里、不解析 Markdown。

理由是误报的代价远高于漏报：一条会误报的警告，用户看两次就开始无视它，那时它连真的
缺口也拦不住了。文档可能用各种形式提到一个仓库（表格行、正文引用、路径 `dc_llm/xxx`），
一律算「提到了」。

### 报给谁：人，不是 agent

结果显示在**底栏消息**里，给用户看。文案带上是哪一份文档——链上可能有好几份，
只说「CLAUDE.md」用户不知道该去改哪个：

```
⚠ ~/work/dc/CLAUDE.md 没提到：dc_desktop、dc-terminal
```

路径用 `widgets::short_path` 缩成 `~`。文案走 `i18n`（`msg::` 里加一条带参函数，
因为要填路径和名字列表；理由见 `i18n.rs` 里 `msg` 模块的注释）。

**不注入给 agent。** 曾经考虑过用 `profile.env` 或 `--append-system-prompt` 把这份事实
送进 agent 的系统提示，否掉了：那样 agent 会同时拿到两个系统提示层面的权威来源，一个说
「浏览器自动化在 dc_workbench」（还带 MUST FOLLOW），一个说「磁盘上有 dc_desktop」，
而它们**互相不知道对方存在**。agent 得自己判断哪个更新，它没有任何依据。这不是修好了
信息，是又加了一个信源。

把人放回回路里才是这次事故真正缺的那一环：只要开工前有一行字摆在用户眼前，他会立刻
纠正 agent，后面整轮弯路都不会发生。

### 何时检查

会话**创建成功之后**，不阻塞创建。检查失败（没有 CLAUDE.md、读不了、目录没权限）
一律静默跳过——这是个提示功能，任何情况下都不该挡住用户开会话。

向上遍历到 `$HOME` 为止（`$HOME` 本身也查），再往上不看：`/Users` 和 `/` 下面没有
项目清单，只有噪音。

### 在界面侧做，不动协议

**这个检查跑在界面进程里，不进守护进程。**

守护进程侧看起来更"自然"（会话就是它起的、它手里有那个目录），但那样结果要经协议
才能回到界面——就得加一个 `Response` 变体、把 `PROTOCOL_VERSION` 再加一，而用户
装了新界面之后跟他说话的还是几天前那个守护进程（这正是版本号存在的理由）。为一条
提示文案付这个代价不值。

界面进程跟守护进程在同一台机器上，读得到同一个文件系统；`App.current_dir` 就是
当前项目，而 `enter_session` 已经保证「进了哪个会话，当前项目就是哪个」。所需的
东西界面全都有。

### 代码位置

- 纯函数 `missing_repos(claude_md: &str, repos: &[String]) -> Vec<String>` ——
  能直接单测，不碰文件系统。这是这个功能的全部逻辑。
- 一个薄的收集层：向上走目录、读 CLAUDE.md、列 git 子目录。
- 新建 `src/claudemd.rs`，不塞进 `session.rs`（那里已经 1200 行了），也不塞进
  `ui/`——它跟渲染无关，只是界面进程碰巧是它的调用方。

## 风险与取舍

**抓不到软过时，这是已知上限。** 这次真正致命的是「workbench 那一行写着浏览器自动化」
——那句话在语法上、在文件里都完全正常，任何自动比对都发现不了。本设计只能打断这条链，
不能修好它。**不要因为有了这个检查就以为清单可信了。**

**每次起会话都报会变成噪音。** 缺口不补，同一句警告会重复出现。这是有意的：它就该
一直烦到有人去补那张表。但如果实测下来确实烦人，下一步是记住「用户已经看过这条」而
不是删掉它。

**多份 CLAUDE.md 时可能一次报好几行。** 链上每一级各查各的。实际情况里通常只有一到
两份，先不做合并，看真实使用再说。

## 测试

- `missing_repos_finds_a_repo_the_doc_never_mentions` —— 核心用例，就是这次的事故
- `missing_repos_accepts_any_mention_not_just_a_table_row` —— 正文里以路径形式出现
  （`dc_llm/xxx`）也算提到，不许报
- `a_directory_without_git_is_not_a_repo` —— `logs` / `tmp` 不报
- `the_walk_stops_at_home` —— 向上遍历不越过 `$HOME`，`/Users` 和 `/` 不查
- `a_claude_md_beside_the_project_is_checked_too` —— 当前目录自己那份也要查，
  不是只查上级
- `no_claude_md_is_silent` —— 找不到就什么都不说，不是错误
- `an_unreadable_claude_md_never_blocks_the_session` —— 读不了也要能开会话

前两条和 `the_walk_stops_at_home` 之外的几条都要能在 `tempfile::tempdir()` 里造出来
（建几个假仓库 = `mkdir -p x/.git`），不依赖真实的 `~/work/dc`。

## 不做

- **不自动改 CLAUDE.md。** dct 只知道目录名，而那张表真正值钱的是「技术栈 / 作用 /
  端口」三列——那些它填不出来。能自动写的恰好是最没价值的一列，而代价是每次起会话
  都可能在用户仓库里产生未提交改动。
- **不检查描述对不对。** 见上面的已知上限。
- **不解析 Markdown 表格。** 宽进严出，见「匹配方式」。
- **不做成阻塞式确认。** 提示就是提示，不该变成一道门。
