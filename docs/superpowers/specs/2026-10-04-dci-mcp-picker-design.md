# dc.ai 帮用户挑最合适的 MCP

日期：2026-10-04
状态：设计草稿，待用户审；没有代码。
来源：用户 2026-10-04：「dci 有个重要的功能就是帮助用户选取最合适的 mcp 来完成用户的工作」，并说「任何第三方的工具」都可以用（授权评估和使用，不等于不审）。这里的 dci 按**菜单栏的 dc.ai（dc-local 仓库）**理解，**没有和用户确认过**。
相关：`2026-10-04-dct-teach-small-model-design.md`（大模型解决问题的过程教会整个系统）、`2026-10-04-ticket-waiver-design.md`（dco 的点击权限）。

## 要解决什么

零编程经验的用户说一句话「让 iPad 上的游戏自动玩」「帮我发一条视频」，系统要自己选对工具。现在的真实情况（2026-10-04 一晚上发生的）：

- 自家的 dco 有隐私闸和「没字不点」的票，但它只能通过「iPhone 镜像」控制 iPhone，**做不了 iPad**，也**不能按坐标点**；
- MCP 市场里有一批第三方工具（mobile-mcp、WDA MCP、Appium 版 iPhone MCP、MetaMask device-mcp、Icemoon 等）能点能划能截图、也支持 iPad，但要 USB、开发者模式、签名一个叫 WebDriverAgent 的小程序，**没有隐私闸和钱档拦截**，接上就能看到、点到手机上所有东西；
- 用户没有能力、也没有时间自己研究这些。

所以「选哪个工具」本身是一个需要系统替用户做的、而且要做对的决定。选错的代价不是慢，是把私人内容和支付暴露给一个没有拦截的第三方。

## 原则

1. **安全优先，再看适配。** 能完成任务但没有拦截的工具，不能排在有拦截的前面；排序先看「会碰到什么数据、有没有闸」，再看「装起来多麻烦、做得好不好」。
2. **自家的优先。** dco（有隐私闸、票、钱档拦截）能做就用 dco；第三方是 dco 做不到时的补位（比如 iPad）。
3. **装之前先审，不装来路不明的。** 用户说任何第三方都可以，这是授权评估和使用，不是免审。
4. **用户拍板。** 装哪个、给什么权限，由用户确认，系统只推荐并说清楚理由和代价，不替他决定；动钱、不可撤回的授权永远要用户本人。
5. **用大白话说。** 不出现 MCP、WebDriverAgent、sha 这类词；说「这个工具能让我控制你的 iPad，但它没有隐私保护，会看到你所有的画面」。

## 工具卡（放进 dcv，一个工具一张）

每个候选工具有一张卡，格式是 dcv 里的一种资料（需要请 dc-vault 加一个 `工具` 类；在它落地之前，先放在 `~/.dct/tools/<名字>.md`，格式相同）。键（草案，按这个顺序）：

```
名字: mobile-mcp
来源: https://github.com/mobile-next/mobile-mcp
许可证: （审过才填）
能做: 点、划、截图、装应用、录屏、按键、深链接
对象: iPhone 真机、iPad 真机、模拟器          # 能控制什么设备
需要: USB 线、开发者模式、WebDriverAgent 签名（免费证书每 7 天重签）
会碰到: 设备上所有应用的画面和操作              # 数据范围
有闸: 没有隐私闸；没有钱档拦截；没有「没字不点」
装的麻烦: 高（要签名、要 USB）
审过: 没有 | 审过 <日期> <谁>（结论一句话）
```

「有闸」「会碰到」「审过」三项是排序的主要依据，不是可选的装饰。

## 选择逻辑（dc.ai 里的一个函数，输入一句话任务，输出一张推荐）

1. **任务 → 需要什么能力 + 对象设备。** 例：「玩 iPad 上的游戏」→ 点、划、截图；对象 iPad 真机。
2. **筛：** 对象设备和能力都满足的卡。
3. **排：**
   - 一级：`有闸` 完整的（隐私闸 + 钱档拦截 + 没字不点）排最前，**自家的在同级里排前面**；
   - 二级：`审过` 的排在没审过的前面；没审过的只能列「建议先审」，不能直接推荐安装；
   - 三级：`装的麻烦` 低的在前；
   - 同级平手时，列出两个并说清取舍，让用户选。
4. **推荐的话（给用户看）：** 「这件事我有两个办法。办法一：用我自带的，只能控制 iPhone，有隐私保护，现在就能用。办法二：用第三方的，能控制 iPad，但它没有隐私保护，会看到你手机/平板上所有画面，要先检查它，大约要花……」
5. **用户选了第三方：** 先走「审」（见下），通过后才装；装好的工具也要记一条（`审过` 更新），下次直接用。

## 审（装之前，只读）

对一个第三方工具，系统（或大模型）做：
- 看**许可证**（能不能这样用）、**维护者和活跃度**（最近提交、star、issue）、**它要什么权限**（读 README 和 manifest）；
- **读源码里和数据有关的部分**：它把截图或文字发到哪里（有没有联网上传）、有没有写到磁盘、有没有执行下载的脚本；
- 产出一段给用户看的结论：「没发现会上传画面的代码」「它会联网到 X」「维护者 1 个人，3 个月没更新」。大模型的结论只是**参考**，不是担保，卡上的 `审过` 要写明是谁、什么时候、看了什么。
- 绝不在审之前安装、运行第三方代码。

## 各部分放在哪（避免把一件事分到四个地方）

| 部分 | 放哪 | 说明 |
|---|---|---|
| 工具卡（数据） | dcv | 用户确认才生效，和游戏资料同一套规矩；dc-vault 加一个类，格式见上 |
| 选择逻辑、推荐的话 | dc.ai（dc-local） | 菜单栏里「这件事有两个办法……」的那张卡；用户点选 |
| 审 | dct（或对话里的大模型）+ dcv 记录结果 | dct 有 `llm` 层可问模型；结果写成卡上的 `审过` |
| 点击、读屏幕的执行 | dco（自家）或装好的第三方 | 自家的有票和闸；第三方的在它自己的约束下 |

## 第一批工具卡的素材（2026-10-04 评估，未审）

mobile-mcp、WDA MCP、iPhone MCP（Appium 版）、MetaMask device-mcp、Icemoon MCP，再加上自家的 dco（有闸）和 dcv。它们要 USB、开发者模式、签名 WebDriverAgent，**没有隐私闸、没有钱档拦截**，能看到设备上所有东西。iPad 目前只有这一类能控制。

## 不做（这一轮）

- 自动安装第三方工具（必须用户确认，且先审）；
- 把审的结论当担保；
- 替用户决定给第三方什么权限；
- 在 dco 里内置第三方工具的调用（dco 不碰 dcv，也不替第三方背书）。

## 先做什么

1. 请 dc-vault 加「工具卡」这一类（或先用 `~/.dct/tools/` 文件）；
2. 写第一批卡（dco、dcv，加 mobile-mcp 作为第一个第三方样本，`审过` 先写「没有」）；
3. dc.ai 里把「选择逻辑」做成一个函数，先只做规则（按上面的筛和排），**不用大模型**；大模型只用在「听懂任务」和「写审的结论」这两步；
4. 审第一个第三方样本（mobile-mcp），把结论写进它的卡。

## 要用户确认的

1. dci 是不是菜单栏的 dc.ai（dc-local）；
2. 工具卡放 dcv（需要 dc-vault 加一类）还是先放本地文件；
3. 「没有拦截的第三方工具」在没审过之前，是**完全不推荐**，还是可以推荐但标红说明（本设计取前者的变体：只列「建议先审」，不推荐安装）。
