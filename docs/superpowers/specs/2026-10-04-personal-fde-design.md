# 个人 FDE：设计（草稿，待用户审）

日期：2026-10-04
状态：草稿，只存本地，没有提交，没有代码。
起因：用户 2026-10-04 说「我们做私人定制的 FDE」「我们目前更应该向个人 FDE 的方向发展」，并确认了定位：不是 AI 工程师，是替身。

## 一句话

**个人 FDE = 先看用户做一遍，再替他做，他一伸手就接管。** 用最小的代价把事办成；写代码和训练专属模型是最后的手段。

## 市面上的 FDE 是什么，我们和它的关系

市面上的 FDE（forward deployed engineer，驻场工程师）是一个真人工程师，驻到客户组织里，在客户真实环境里开发、定制、部署，一直负责到软件在生产环境里跑起来（Palantir 创造了这个角色；2026 年 OpenAI、Anthropic、Google 都在大量招，年薪约 21.5 万到 78 万美元以上）。来源：[维基百科](https://en.wikipedia.org/wiki/Forward_Deployed_Engineer)、[Netguru](https://www.netguru.com/blog/forward-deployed-engineer-role-guide)、[薪酬报告](https://getperspective.ai/blog/2026-forward-deployed-engineering-compensation-report-1200-fdes)（以上只读到摘要，未逐篇核实）。

| | 市面上的 FDE | 我们的个人 FDE |
|---|---|---|
| 是谁 | 一个真人工程师 | 产品（dco、dct、dcv、dc.ai）加用户 |
| 服务谁 | 大企业、大客户 | 没有预算请驻场工程师的个人和小团队 |
| 怎么学客户的活 | 开会、画流程、写代码 | 先看用户做一遍（示范） |
| 价格 | 一个人几十万美元一年 | 目标几乎免费，越用越便宜（**未实测**） |

**定位：** 我们是「FDE 里重复操作那一部分的 AI 替身」。FDE 的工作一部分要工程师判断和写代码，另一部分是每天照着流程点来点去，后者占很多时间也最贵。我们先把后者做掉。**不说「平替」**：我们现在不能保证「流程真的变好了」（FDE 要对结果负责），也不处理没见过的情况。

## 解决一件事的顺序（用户 2026-10-04 定）

1. 先找现成的（网上有没有人做过，有没有现成工具或 MCP）。
2. 审后直接用。
3. 没有就用 dco 操作界面，靠示范和 dcv 里的资料。
4. 大模型兜底，把它解决的存进 dcv。
5. 最后才选一个：**写代码**（卡在「没有这功能」）或**训练专属模型**（卡在「每次问大模型太贵太慢」，数据要攒到上千条）。两者都要测、要维护、要负责。

## 核心回路（整个 FDE 的骨架）

```
用户示范一遍（dco demo）
   -> 示范变成 dcv 里的「流程草稿」（带 --learned-from demo:编号）
   -> 用户确认（dcv approve）
   -> dco 按已确认的流程重放
   -> 每次重放记录：用了多久、问过几次大模型、有没有出错
```

各部分的职责：
- **dco：** 眼和手。记录示范，重放流程，验票，隐私闸，急停，听用户说话（语音，只输出文字，不执行）。
- **dct：** 大脑。把示范转成流程草稿；重放时判断「画面对不对」；没进展就停下；管上下文和失败账；语音指令走白名单。
- **dcv：** 记忆。每个客户一个库：他的流程、他常用软件的界面笔记、他定的规矩、试过不行的、画面地图。**所有用户确认前的内容都是草稿。**
- **dc.ai（菜单栏）：** 只显示状态、转发按钮，不做判断。

## 闸门（不变）

- **隐私：** 私人画面什么都不给；麦克风默认关，开始听只能用户点章鱼，dct 没有开麦工具；原始声音不落盘。
- **钱：** 动钱一律用户本人确认（Touch ID）。
- **不可撤回的删除和授权：** 保持要本人签。
- **语音永远不算授权：** 人声可以被旁边的视频或别人冒充。语音指令只能触发白名单里的普通指令（开始示范、结束、继续、去某个场景）。
- 除了隐私和钱，其余放行（用户 2026-10-03 定）。

## 出错时怎么办（现在还没做，必须做）

- **发现：** 重放时每一步靠 dco 的「画面变没变」和文字判断，不靠模型自己说。
- **停：** 连续没进展、碰到没学过的画面、出现意外弹窗，就停下，不乱试。
- **说：** 用大白话告诉用户停在哪一步、为什么，并请他示范这一步；示范完把新的一步补进流程草稿。
- **不重试已试过不通的办法：** 失败组合按（物品，位置）记账，存 dcv；只有出现新状态才清掉相关记录（策略调研第 3 条）。

## 第一个实验

选一件真实的小任务（用户定），把「示范 -> 草稿 -> 确认 -> 重放」整条线跑通一遍。要求：步骤基本固定，在 Mac 或 iPhone 上能做完，做错了不出大事（先从「存成草稿、不发出去」开始）。

要量的：
- 第一遍（摸索 + 示范）：大模型调用次数、用时、token。
- 第二遍起（重放）：同样的数字，以及有没有出错、停在哪。
- 倍数 = 第一遍 / 重放。**这个数字没有实测之前，对外不说「省了 N 倍」。**（之前的估算：对每步都问大模型约 5 倍，是假设，不是结果。）

## 不做（这一轮）

- 写代码当解决手段。
- 训练专属模型（数据不够，见 [[dct-small-model-training-direction]] 的结论）。
- 让大模型在没有示范的情况下独自探索复杂冒险游戏（实测和调研都说明现在做不到；见 `games:adventure-game-strategy-*`）。
- 任何会碰钱、会删除、会授权的自动操作。

## 还没定的（需要用户）

1. **服务谁：** 先是用户本人（运营自己的账号），还是以后给别人？
2. **做到什么程度：** 只存草稿让他点发送，还是直接发出去？
3. **怎么收费：** 按月，还是按「替他省了多少」？
4. **第一件真实任务是什么？**
5. **Windows：** 很多客户用 Windows，而 dco 现在只能在 Mac 上跑。第一版只做 Mac 可以吗？
6. **「挑工具」归哪个项目：** 之前以为是 dc.ai，但它的会话说规定里不做判断；要用户定。
