# dct 看板按项目过滤 —— 设计

**状态：** 已实现（`feat/board-project-scope`），待用户 review 设计判断
**位置：** 换项目重做四步（D → A → B → C）的第一步
**取代：** 无。`2026-08-03-dct-project-switch-design.md` 描述的 `p` 键换项目本身保留，这里补的是它一直缺的那一半

## 问题

底栏写着「当前项目：~/work/dc/dc-terminal」，看板却列着 `~/work/dc/dc_desktop` 的会话。
看板从来没有按项目过滤过 —— `board.rs:68` 直接迭代 `app.sessions`，那是守护进程返回的全量列表。

用户对这一版换项目功能的评价是「完全是混乱的」，点名四条症状。其中两条落在这份 spec 里：

**症状一：看板混着所有项目的会话。** 确认存在，机制如上。

**症状二：「同一个 session 变成不同的项目」。** 调查结论是**它不是独立的 bug，是症状一的观感后果**：

- `session.dir` 在 `src/session.rs:194` spawn 时写入一次，全仓再没有第二处写它。
- `app.current_dir` 的全部用处只有五处：四处建**新**会话（`pick.rs:72,131`、`mod.rs:244,761`）
  和一处画底栏标题（`mod.rs:959`）。没有一处够得着已存在的会话。
- 会话只活在守护进程内存里，没有落盘/重载路径，不存在反序列化丢 `dir` 的可能。

于是真实机制是：列表不过滤，底栏却宣称「当前项目：X」。换项目之后**列表一行没变、标签变了**，
屏幕上每一条就都读作「属于 X」。修好症状一，症状二一并消失。

> 待用户确认：如果换项目后曾见过某个会话**自己那一列路径**发生变化，那才是另一回事，
> 本 spec 不覆盖，需要单独复现。

## 范围

**要做：** 看板列表与九宫格按当前项目过滤；一个键切到「全部项目」视图；两种视图的空状态文案；
过滤后光标/焦点的收拢；路径归一化比较。

**不做：**

- **不改守护进程协议。** `Request::List` 不加 `dir` 参数，过滤全部发生在界面进程。守护进程
  是常驻的、可能同时服务多个界面的进程，让它记住「谁的当前项目是什么」是把状态放错了地方。
- **不持久化作用域。** 每次启动都从「只看当前项目」开始。这是安全的默认值，不需要记忆。
- **不改 `session.dir` 的存储形式。** 归一化只发生在比较时，显示什么保持原样（见「路径比较」）。
- **不做列表/九宫格的模式切换与记忆** —— 那是 B。本 spec 里两种视图各自被过滤，但谁是默认、
  怎么切换、切换记不记住，一律不动。

## 架构

新增一个派生字段，views 全部改读它，其余结构不动。

```
App {
    sessions: Vec<SessionInfo>,   // 守护进程返回的全量，只写不读（除了重算 visible）
    visible:  Vec<SessionInfo>,   // 派生：当前作用域下真正上屏的那些
    scope:    Scope,              // CurrentProject | AllProjects
    ...
}

enum Scope { CurrentProject, AllProjects }
```

**为什么是「派生出一份 Vec」而不是「过滤器函数」或「下标映射表」：**
`board.rs`、`grid.rs`、`mod.rs` 里所有的光标、焦点、`session_action` 都是**按下标**索引
`app.sessions` 的。换成一份内容已经过滤好的 `visible`，这些调用点一个字都不用改逻辑，
只把 `app.sessions` 换成 `app.visible`。下标映射表则要求每一处都记得转换一次，
漏一处就是「选中第 3 行、停掉了第 5 个会话」这种最难查的 bug。

`sessions` 保留全量是因为「全部项目」视图要用，而且守护进程的响应不该被界面的显示决定丢弃。

### 重算 `visible` 的三个触发点

只有这三个，多一个都是重复计算，少一个都是屏幕说谎：

1. 会话列表刷新之后（`need_sessions` 那条路径拿到 `Response::Sessions` 时）
2. `scope` 被切换时（`a` 键）
3. `current_dir` 被改变时（选择器确认，`pick.rs:216` 与 `pick.rs:287`）

重算是一个纯函数，可以单测，不碰 socket：

```rust
fn visible_sessions(all: &[SessionInfo], scope: Scope, project: &Path) -> Vec<SessionInfo>
```

### 路径比较

`session.dir` 和 `current_dir` 虽然都源自同一个字符串（建会话时界面把 `current_dir` 发过去，
守护进程原样存下），但用户可以从手输路径进来，带尾随斜杠、`.`、或者走符号链接，
于是两边可能字面不等而实际同一个目录。

**规则：比较时两边都 `canonicalize`，显示时都用原样。** 显示不动是为了不让 macOS 上
`/tmp` 变成 `/private/tmp` 这种事污染界面。

`canonicalize` 是系统调用，不能每帧对每个会话做一次。落点是重算 `visible` 的那三个触发点——
它们本来就不在每帧路径上。`canonicalize` 失败（目录已被删）时**退化成原字符串比较**：
一个指向已删目录的会话仍然应该出现在它原本的项目下，而不是从两个视图里同时消失。

### 按键

`a` = 在「只看当前项目」和「全部项目」之间切换。看板上 `a` 未被占用（现有：`q n N p c g u s d`、
`↑↓`、`Enter`），九宫格上同样空闲。两个视图共用同一个键、同一个 `app.scope`，
因为它们是同一批会话的两种画法，作用域跟着用户走而不是跟着视图走。

### 界面

| | 只看当前项目 | 全部项目 |
|---|---|---|
| 列表标题 | `dct 会话看板` | `dct 会话看板 · 全部项目` |
| 列表的路径列 | 隐藏（底栏已经写了当前项目，每行再重复一遍是浪费 22 列） | 显示，就是现在的样子 |
| 九宫格格子标题 | 只有会话号和 agent 名 | 追加项目名 |
| 空状态 | `这个项目还没有会话，按 n 开一个，按 a 看全部项目` | `还没有任何会话，按 n 开一个` |

列表在「只看当前项目」时腾出的 22 列给 `activity`——那一列现在被截到 60 字符，
是屏幕上最先被截断的信息。

### 光标与焦点的收拢

过滤会让列表变短，而 `list_state.selected()` 和 `View::Grid { focus }` 是下标。
`grid.rs:63` 有一条 `debug_assert!(focus < total)`，release 下越界会让 `total - page_start` 下溢。

**规则：每次重算 `visible` 之后，立刻把光标和焦点收拢进 `0..visible.len()`。**
收拢到**末项**而不是首项 —— 用户的注意力在列表尾部时，弹回第一行会让他以为选中的会话没了。
`visible` 为空时光标置 `None`、焦点置 `0`（此时画的是空状态，没有格子可焦）。

### 附加中的会话跑出作用域

从「全部项目」视图进了一个别的项目的会话，按 F2 回看板时，那个会话不在当前作用域里。

**决定：进入一个会话时，如果它的目录不是当前项目，就把当前项目切成它的目录。**

理由是「你在哪个会话里，当前项目就是哪个」这条规则本身就是用户对症状二的期待，
而且它顺带让 `n` 新建会话落在你正看着的那个项目里，不需要先退出去换一次项目。
底栏的「当前项目」会随之改变，并给一句 `已切到 <项目>` 的消息说明刚才发生了什么——
静默改变当前项目正是这一版被判为「混乱」的原因，不能再犯。

> **需要你确认这一条。** 另一个选择是不动当前项目，让那个会话在看板上暂时看不见。
> 我认为那更糟（会话像是消失了），但这是全份 spec 里唯一一处我在替你做判断。

## 测试

按 TDD 写，先红后绿。纯函数的部分不碰 socket。

**`visible_sessions` 纯函数：**

1. 混合项目的列表 + `CurrentProject` → 只剩当前项目那些，顺序保持
2. 同一份输入 + `AllProjects` → 原样全量返回
3. 当前项目一个会话都没有 → 空 Vec，不 panic
4. `current_dir` 带尾随斜杠 / 走符号链接 → 仍然匹配得上（归一化生效）
5. 会话目录已被删除（`canonicalize` 失败）→ 退化成字符串比较，该会话仍归在它原本的项目下

**收拢：**

6. `visible` 从 5 条缩到 2 条、`selected` 停在 4 → 收拢到 1（末项），不越界
7. 同样的收缩下 `Grid { focus: 4 }` → 收拢到 1，`move_focus` 的 `debug_assert` 不触发
8. `visible` 变空 → `selected` 为 `None`，空状态文案上屏

**触发点：**

9. 改 `current_dir` 之后 `visible` 立即重算（不必等下一次 `need_sessions`）
10. 按 `a` 之后 `visible` 立即重算，标题变成「· 全部项目」

**渲染：**

11. 只看当前项目时，列表不出现路径列
12. 全部项目时，列表出现路径列、九宫格格子标题带项目名
13. 空作用域的两条文案分别上屏（当前项目 / 全部项目各一条）

**回归：**

14. 症状一：`current_dir = A`，会话分属 A 和 B → 屏幕上不出现任何 B 的会话
15. 进入一个跨项目的会话 → `current_dir` 变成该会话的目录，且给出 `已切到 …` 的消息

## 实施中发现的一处计划外改动

加 `a` 键时撞上一个**既有** bug：底栏的按键表是单行截断的，原文案已经 91 列宽，
而 80 列终端上右段只剩 57 列——`u 回滚` / `s 停止` / `d 改动` 长期被右端整个截掉，
其中两个是不可撤销的操作。`a` 只是把 `u 回滚` 也挤了出去，让它暴露出来。

修法：底栏从 3 行改成 4 行（上下边框 + **两行**文字），并且自己折行而不是用
ratatui 的 `Wrap`——`Wrap` 在任何空白处断，会把「p 换项目」拆成行尾一个孤零零的
`p` 加下一行的「换项目」，屏幕上看起来像两个键、其中一个还没名字。折行逻辑是
`widgets::wrap_help`，只在分隔符（两个半角空格 / 一个全角空格）处断。

代价是内容区少一行。收益是看板和九宫格的**每一个键**在 80 列下都真的画得出来，
由 `every_board_key_is_actually_on_screen_at_eighty_columns` 和它的九宫格版本钉住。
