## 发布流程

1. 学生在 DCT 选择当前项目，点击「发布作品」。
2. 服务仅收集明确的静态产物目录，校验入口、文件类型、数量和总大小，
   排除凭据、隐藏文件、源码配置、依赖目录及符号链接。
3. 生成不可变版本与预览链接。学生看到作品名称、预览和「确认提交」。
4. DCT 服务将学生工作区身份、项目标识和版本通过服务间凭据提交至网站。
   网站创建或更新同一个项目，不因重试产生重复作品；学生不能指定其他人的归属。
5. 暂按网站现有规则进入待审核状态。老师审核后出现在现有作品区。
   此规则已向用户发起可选问题；用户尚未回复时不把“立即公开”作为默认值。
6. 再次提交保留当前已审核版本，新版本审核通过后才切换公开链接。
   老师可撤下作品或回退上一已发布版本。

## 网页托管与隔离

作品区页面继续使用 `https://ai.tzspace.cn/projects`。
学生 HTML、JavaScript 和静态资源拟由独立子域名 `works.dataclue.cn` 托管，
与 `dataclue.cn` 管理台及 `ai.tzspace.cn` 网站登录保持不同 origin。
服务不向作品域名设置管理或学生登录 cookie；现有 cookie 保持 host-only。
独立域名仅提供静态内容，不代理课堂 API，不开放服务端执行。

## 共用 skill

同一份发布规则指导 agent 生成合适的静态产物、解释校验错误并准备预览。
公共发布动作仍由学生在 UI 确认。agent 不持有网站管理员凭据，
不自行 SSH、改反代或直接写作品数据库。

## 验证要求

- 学生间项目与发布版本隔离，过期或撤销身份不能提交。
- 重试不重复创建作品；新版本不会绕过审核改变旧公开内容。
- 不收集隐藏凭据、符号链接、目录外文件，超限明确失败。
- 作品脚本无法读管理台 cookie、API 或操作学生工作区。
- 预览、提交、审核、更新、回退、撤下在浏览器中实际验证。
- 作品在学生结束练习、停止容器后仍可访问。
- 网站升级前备份数据库，部署后验证真实写入，保留原网站项目和报名数据。
