# Fix 3 — 看板列表对这个功能零测试覆盖

来源：`final-review-report.md` 的 Finding 6（Important，四条合并阻塞项之一）。
**这是四条里最大的一个洞，而且盖的正是 README 首要宣传的那个界面。**

**文件：** `src/ui/board.rs:211,214`。

## 现状

分支把看板的会话行从

```
pad_to(&s.profile, 10)  +  truncate(&s.activity, 76)
```

改成了

```
pad_to(&truncate(session_label(s), 15), 16)  +  truncate(&s.activity, 70)
```

也就是**从 activity 那里挪了 6 列给名字**。

## 四个变异，一个测试都没红

| 变异 | 结果 |
|---|---|
| `session_label(s)` → `s.profile`（**列表永远不显示名字**） | 无测试失败 |
| 删掉 `truncate(…, 15)` | 无测试失败 |
| 删掉 `pad_to(…, 16)` | 无测试失败 |
| activity 的 `70` 改回 `76`（**列预算被破坏**） | 无测试失败 |

README 明确承诺名字会出现在「会话列表」里。**没有任何东西钉住这一点**，
分支重写的那套列算术也没有。

## 算术本身是对的（不要改它，只要盖住它）

`truncate(s, 15)` 返回**至多 15 个显示列**，或者在真的发生截断时**正好 16 列**
（`…` 是在宽度检查**之后**追加的），所以 `pad_to(…, 16)` 得到的正好是 16，
行总宽保持 `8 + 16 + 70` 不变。

**这个推理已经过评审确认成立。** 本条任务是给它加守卫，不是改它。
如果你在核对时发现这个推理有问题，**先在报告里说清楚再动手**，不要默默改掉。

## 要改什么

加看板行的测试：

1. **一条断言名字被画出来、而 profile 没有**
   —— 这条直接杀掉「`session_label(s)` → `s.profile`」那个变异
2. **一条断言 24 字符的名字不会把 activity 列挤歪**
   —— 这条杀掉截断、补齐、以及 70/76 那三个变异

## 测试要求

四个变异**每一个都要有测试杀掉它**。改完之后**逐个亲手验证**：
把变异改进去、跑测试、确认变红、改回来。**这就是本条任务的验收标准。**
