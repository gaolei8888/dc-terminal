# 跟进 2 —— 两个集成测试在满载下假失败

来源：全分支终审的跟进项 T3（判定**不阻塞合并**，用户选择在合并前做掉），
以及更早那份终审的 Finding 10。

## 现状

两个测试在满载并行 `cargo test` 下会红，单独跑和 `--jobs 1` 下干净：

- `tests/grid_reply.rs`（两条测试）
- `src/ui/mod.rs::entering_a_session_always_lands_at_the_bottom_even_without_a_resize`

**根因是同一个，而且和这个分支无关**（`grid_reply.rs` 是 `809c595` 加的，
远早于本分支）：

两个测试都在同进程线程里起一个**真 daemon**（`crate::daemon::run(&s)`），
然后通过 socket 用内置的 `shell` profile 建会话。而 `profiles/shell.toml` 是：

```toml
command = ["/bin/zsh"]
```

**那是开发者自己的登录 shell，会 source 他真实的 `~/.zshrc`。**
提示符多久能画出来，取决于那份 rc 文件有多重（插件、补全、版本管理器……），
而测试拿一个固定的截止时间去赛它。满载时输掉。

`tests/grid_reply.rs:41-50` 的注释自己就说了：「这里跑的是用户自己的登录
shell」，「等『屏幕上有了非空白内容』就够了」。那道等待本身是对的，
**赌的是它能在截止时间内完成**。

## 要改什么

**别再用登录 shell。** 让测试用一个自己写的 profile，指向一个启动瞬间完成、
不读任何 rc 文件、输出确定的程序。

数据路径全部从 socket 路径派生（README：「每一条数据路径都是从 socket 路径
派生的，测试把它指向临时目录」），而 profile 目录**每次请求都重新读**
（README：「目录在每次请求时被重新读取」）。所以测试可以在自己的临时 home 里
写一个 profile TOML，daemon 就会看见它 —— **不需要动产品代码**。

程序选什么由你定，但它必须满足：

1. **启动没有可观测的延迟**，不读用户环境里的任何东西
2. 让 `grid_reply.rs` 那条契约仍然可验证 —— 见下

`src/session.rs` 的测试里已经有几个现成的样子可以参考
（`fake_agent()`、`finishing_agent()`、`busy_only_agent()`），
但它们走的是进程内的 `register_profile`，而这两个测试走 socket，
**拿不到那个入口**，得靠磁盘上的 profile 文件。

## grid_reply.rs 的契约不能被稀释

那个文件存在的理由写在它开头，读一遍再动：

> 界面侧 `grid::send_reply` 把一句话拆成**两次** `Input`：先送文字，
> 再送一个**空串**。空串在守护进程侧就是「按回车」。
> **文字 + 空串真的等于「打了一行字并回车」。**
> 它一旦变了，界面会安静地退化成「字发过去了但 agent 一直在等回车」——
> 用户以为自己回过话了，其实对面还停着。

关键在 `:92` 那条注释：**那行字在按回车之前就已经回显在屏幕上了**，
所以「屏幕上出现了这行字」**证明不了**回车送到。测试必须能区分
**回显**和**真的执行了**。

**你换的那个程序必须保留这个区分能力。** 如果它做不到，
这条测试就被你稀释成了一条永远会过的测试 —— 那比 flaky 更糟，
而且正是这个分支已经栽过四次的坑。

在报告里明确写出：**换了程序之后，「只回显、没执行回车」这种情况
靠哪一条断言被抓住。**

## 测试要求

- 两个测试的**原有语义一条都不能丢**。改的是它们怎么拿到一个可预测的
  子进程，不是它们验什么。
- **亲手验证它们仍然会因为正确的原因失败**：
  - `grid_reply.rs`：把界面那两次 `Input` 里的空串去掉（模拟「回车没送」），
    测试必须红
  - `entering_a_session...`：把 `enter_session` 里那次显式
    `Request::Scroll { by: Bottom }` 去掉，测试必须红
- 满载并行下重复跑几轮（比如 `cargo test` 连跑 5 次，不加 `--test-threads=1`），
  确认不再间歇性变红。**这一条是本任务的验收标准**，跑不出来就说跑不出来。

## 全局约束

- **本简报不是权威。** 这一轮里五份简报，每一份都被实施者抓出过一处不准确。
  动手前自己把 `profiles/shell.toml`、两个测试、以及 profile 的加载路径
  读一遍核对，发现问题**先报告再动手**。
- **产品代码原则上不该动。** 这是测试基础设施的问题。如果你认为必须动产品
  代码才能修，**先报告理由**，不要直接改。
- 反方向的陷阱：这个分支有六条命名测试**在负载下退化成假绿而不是假红**。
  你修的这两条是假红。**别把假红修成假绿** —— 加长超时、放宽断言、
  或者让测试在等不到时静默通过，都属于这一类。
- 每个用户能看到的字符串写给没编过程序的人。
- 提交信息用英文，**不要 AI 署名行**。
- 收尾跑：`cargo test -- --test-threads=1`、`cargo fmt --check`、`cargo clippy --all-targets`。
