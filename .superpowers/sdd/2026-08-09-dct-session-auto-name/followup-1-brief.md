# 跟进 1 —— 失败提示改用会话名 + 选择器让异常目录名看得见

来源：全分支终审的两条跟进项（都判定为**不阻塞合并**，用户选择在合并前顺手做掉）。

这是两处互不相关的小改动，放在一个任务里是因为它们都只动界面显示层。

---

## 第一件：失败提示叫的是 profile，不是会话名

**文件：** `src/ui/app.rs:266`

```rust
self.message = Msg::err(crate::i18n::msg::session_failed(
    self.lang, s.id, &s.profile,
));
```

弹出来的是「会话 3（claude）出错了」，而**其他每一处**都已经改成叫会话名了
（看板列表、九宫格标题、回复框的收件人行、附着标题）。

**出错提示是最不该叫错名字的地方。** 用户正在被告知有东西坏了，这一刻他要靠
这句话去找是哪个会话，而屏幕上别的地方都在用另一个称呼。

**要改什么：** 改用和其他地方同一个来源。**不要自己拼字符串** ——
`src/ui/widgets.rs` 里的 `session_label` 就是「一个会话该显示成什么」的
唯一决定处，README 里明确写着「一个共享 helper 决定为一个会话画什么，
这些地方才不会像各自格式化的字符串那样悄悄跑偏」。用它。

`session_failed`（`src/i18n.rs`）已经接受 `&str`，改起来是换一个实参。

**测试要求：** 断言一个有名字的会话失败时，提示里出现的是名字；
一个没名字的会话失败时，回落到 profile 名（`session_label` 本来就这么做）。

## 第二件：目录名里的控制字符，在你选它的那一刻是看不见的

**文件：** `src/ui/pick.rs:494`（显示）、`:236` 和 `:278`（真正打开）

Fix 1 给 `truncate` 加了控制字符过滤，于是选择器**显示**目录名时是干净的
（`:494` 的 `truncate(&r.name, 30)`）。

但真正打开目录用的是 `p.cwd.join(&row.name)` —— **原始名字**。

**这是必须的，别去动它。** 目录名是真实的文件系统路径，洗过之后就
`join` 不到那个目录了。**任何把清洗后的名字拿去拼路径的改法都是错的**，
会变成「选了一个目录，打开的是另一个/打不开」。

真正的问题是别的：POSIX 目录名里只有 `/` 和 NUL 是禁止的，`0x1b` 完全合法。
于是一个名字里带转义序列的目录，在选择器里**看起来和一个正常目录一模一样**，
用户没有任何办法在做选择的那一刻发现它不对劲。

### 要改什么

**保持显示清洗（现状不动），但给这类目录追加一个压暗的提示标记**，
让用户在选中之前就能看见这一行不正常。

- 标记压暗，和旁边那个 git 仓库标记（`" ●"`, `:492`）同一个处理 ——
  它是辅助信息，不该比目录名还抢眼
- 文案写给没编过程序的人：**不要出现「控制字符」「转义序列」「0x1b」**
  这类词。说的是这个名字里有看不见的东西，不是它的编码构成
- **不用 emoji 当图标**（房规）
- 中英文都要有，走 `src/i18n.rs` 的 `Key` + `text()`

### 测试要求

- 名字含控制字符的目录 → 渲染结果里出现那个标记
- 正常目录 → **不出现**标记（这条同样重要，否则每一行都挂着它）
- **打开路径用的仍然是原始名字** —— 这条是本节的安全底线，必须有测试钉住。
  一个名字含 `\x1b` 的目录，选中之后拼出来的路径必须和文件系统上那个
  真实目录逐字节相等
