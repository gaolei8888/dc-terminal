# dc-workspace —— 浏览器里的 dct

学生本地什么都不装，打开一个地址，看到的就是完整的 dct 看板，agent 跑在服务器上。
关掉浏览器，会话照跑。

服务的是**压根没有合适环境的那批人**：老机器、没有管理员权限的公司电脑、
Chromebook、平板。根目录 README 里那张硬件表对他们是一句「你不合格」，
这个镜像是那张表的出口。

计划和进度：[`../docs/superpowers/plans/2026-09-06-dc-workspace-phase1.md`](../docs/superpowers/plans/2026-09-06-dc-workspace-phase1.md)

## 起一份

```sh
docker compose -f container/compose.yaml up -d --build
```

然后从日志里拿那条链接（下一节），用浏览器打开它。**直接打开
<http://127.0.0.1:7681> 只会看到「要一条完整链接」**——门在那儿。

停掉、连状态一起删掉：

```sh
docker compose -f container/compose.yaml down     # 留着卷，下次起来东西还在
docker compose -f container/compose.yaml down -v  # 连卷一起删，全清
```

## 进门要一条链接

起来之后，钥匙和链接印在日志里：

```sh
docker compose -f container/compose.yaml logs dc | grep '#t='
# http://127.0.0.1:7681/#t=<64 个十六进制字符>
```

**那条链接本身就是钥匙。** 点开一次就换成一个 30 天的 cookie，地址栏里那一截
随即被抹掉，之后刷新、重开浏览器都不用再找它。别把它发到公开的地方，也别把
容器日志贴出去。

只想重新拿一次链接（不重启）：

```sh
docker compose -f container/compose.yaml exec dc dct gate --link --url http://127.0.0.1:7681
```

**换钥匙**（作废所有已经发出去的链接）：删掉 `~/.dct/secrets.toml` 里的
`__gate__` 那一项再重启容器。还没有一条专门的命令，那在计划的任务 6 里。

门的行为，一句话：没带对钥匙的请求一律 401，且**从响应上分不出路径存不存在**
（`/ws`、`/token`、`/随便什么` 三条响应逐字节相同）。唯一的例外是 `GET /`
——它答的是门口那一页，因为钥匙在 fragment 里，而 fragment 根本不发给服务器，
把 `/` 也锁上就成了一个自己锁死自己的循环。那一页里没有任何用户数据。

## ⚠️ 但它**不加密**

明文 HTTP 上，cookie 里那把钥匙每个请求都在线上裸奔。所以 `compose.yaml` 里
端口仍然绑在 `127.0.0.1`，不是 `0.0.0.0`。

要给别人用：

1. 在前面架一层带 TLS 的反代；
2. 把 `DCW_PUBLIC_URL` 指到反代那个地址上（门用它拼链接，容器自己不可能
   知道外面看到的是什么地址）；
3. 端口映射改成只让反代够得着。

这跟 `dct-srv` 里 `must_be_loopback` 拦的是同一件事，理由也是同一条：
没有加密之前，不许当成对外可用。

另外两条明说的边界：

- **鉴权是一条 TCP 连接查一次**，在它的第一个请求上。之后就是一根字节管道。
  拿到过钥匙的人可以在同一条连接上继续发请求——而他本来就有钥匙。
- **ttyd 只绑容器内环回**（`--interface 127.0.0.1`），门是唯一对外的进程。
  这一条是网络层面成立的，不是靠「我们没映射那个端口」。

## 契约：镜像只认这几样

**这个镜像不知道自己被起了几份、挂了什么卷、前面有什么反代。** 它只认下面
这张表。加一样就是改契约，改 Dockerfile 的时候要同时改这里。

### 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `HOME` | `/home/dc` | `~/.dct` 下面那一堆（`secrets.toml` / `projects.json` / `last-sessions.toml`）全靠它推出来 |
| `LANG` | `C.UTF-8` | 不给就是 POSIX，中文在看板里变问号 |
| `TERM` | `xterm-256color` | **别删。**守护进程在容器里没有终端可继承，不给的话会话里是 `dumb`：`tput` 报错、`clear`/`less`/`vi` 全废 |
| `DCT_LANG` | `zh` | 看板语言。发到别处用 `-e DCT_LANG=en`。学生在界面里改过之后以存的为准 |
| `DCW_PORT` | `7681` | **对外**那个端口，`dct gate` 守着它。不是 ttyd 的端口 |
| `DCW_TTYD_PORT` | `7682` | ttyd 在容器内环回上监听哪个。基本不用动 |
| `DCW_PUBLIC_URL` | 空 | 外面看到的地址前缀。门用它拼那条发得出去的链接；不给就按容器网桥地址猜一条，并明说是猜的 |

### 卷

| 路径 | 丢了会怎样 |
|---|---|
| `/home/dc/.dct` | 密钥、项目列表、上次的会话全没了 |
| `/home/dc/.claude` | 对话记录没了，`--continue` 接不回去。会长，实测一周 185 MB |
| `/home/dc/work` | 学生的代码 |

### 端口

容器里 `7681`：**只有那道门**在上面（HTTP + WebSocket）。ttyd 在 `7682`，
只绑容器内环回，从容器外和同网络的别的容器都够不着。

### 构建参数

| 参数 | 默认 | 用途 |
|---|---|---|
| `NPM_REGISTRY` | `https://registry.npmmirror.com` | 跟 `runtime.rs` 的 `CN_NPM_REGISTRY` 保持同一个源 |
| `TTYD_URL` | 空（走 GitHub） | **国内机器上必给**：直连 GitHub 会在 302 之后卡死。只给 URL 就行，哈希是钉死的。例：`https://gh-proxy.com/https://github.com/tsl0922/ttyd/releases/download/1.7.7/ttyd.x86_64` |
| `TTYD_SHA256` | amd64 的那一个 | 只有换架构（arm64）时才要给 |
| `APT_MIRROR` | 空（Debian 官方源） | **国内机器上几乎必给**，见下面那段。例：`http://mirrors.aliyun.com/debian`（**必须 http**，见下） |
| `RUST_TAG` | `1-slim-bookworm` | 构建阶段的 rust 镜像 |

**`APT_MIRROR` 在国内的机器上几乎是必给的。** 之前这里写着「基础镜像不需要换
国内源」——那句话是在一台**加州**的开发机上量的（Docker Hub 拉底包 5 秒），
换到目标机器上就不成立了：2026-09-08 实测，**一个 apt 步骤 1343 秒（22 分钟）**，
而这样的步骤有两个。这是今天第二次栽在「从错的地方量」上，所以写清楚。

**`APT_MIRROR` 必须给 `http://` 的地址。** 这一步要装的正是 `ca-certificates`，
在它装上之前 apt 验不了任何 TLS 证书，给 https 的源会直接失败：
`Certificate verification failed: The certificate is NOT trusted.`
Debian 自己的默认源用 http 也是这个原因——安全性不靠 TLS，apt 验的是每个包
的 GPG 签名。

Docker Hub 那一段仍然是快的（他们的 daemon.json 里配了 registry 镜像），慢的是
**构建过程中的 apt**，两件事。GitHub 拉 ttyd（1.36 MB）通，但也慢，网络不行的
地方用 `TTYD_URL` 换源。

只钉了 **amd64** 的 ttyd 校验和。arm64 要自己下 `ttyd.aarch64` 算出 sha256
用 `--build-arg` 传进来——不传的话构建会直接失败并说明原因，不会悄悄建出一个
跑不起来的镜像。

## 代码放哪儿：两种，两套代价

`git.rs` 的检查点是守护进程在项目目录上做的，守护进程在容器里，所以被快照的
目录必须在容器里看得见。

| | 命名卷（默认，推荐给训练营） | 绑定挂载宿主目录 |
|---|---|---|
| IO | 原速，git 检查点原速 | Windows/macOS 上慢，编译和 `node_modules` 明显拖 |
| 改代码 | VS Code Dev Containers / Remote-SSH，或干脆只让 agent 改 | 本地编辑器照常 |
| 咬人的地方 | 宿主上看不到文件，要导出得走命令 | 换行（`core.autocrlf`）和文件权限会咬 git 检查点 |

换成绑定挂载：把 `compose.yaml` 里 `- work:/home/dc/work` 改成
`- ./work:/home/dc/work`。

**两条路径上的检查点和撤销都实测过了**（2026-09-07）：开 agent 会话 → 改文件
→ `d` 看改动 → `u` 撤销，内容还原、快照之后新建的文件被清掉。绑定挂载那条是
在**宿主那一侧**看的结果。

两条实测出来的代价，比原先估的具体：

- **文件权限：真的咬。** Docker Desktop 的绑定挂载全是 `root:root 0777`，
  git 于是把每个文件都记成 `100755`。容器里前后一致，检查点和撤销不受影响，
  但同一个仓库在宿主上用真 git 打开会看到**每个文件都是模式变更**。
  （另外：正因为属主是 root 而容器里跑的是 dc，镜像里必须有
  `git config --system --add safe.directory '*'`，否则 git 直接拒绝干活。
  它安全的前提是**一人一容器**。）
- **换行：没咬。** 容器里的 git 没设 `core.autocrlf`，CRLF 文件在快照里是
  逐字节原样的，`d` 也不会把它误报成改动。风险在**宿主**那一侧：宿主的 git
  如果 `autocrlf=true`，会在 agent 干活的同时改写工作区文件。

**只支持 docker。** rootless podman 的 uid 映射咬的正是上面那条权限
（`safe.directory` 那一行是按 docker 的 `root:root 0777` 挂法来的），所以
上面这段结论只对 docker 成立；真要上 podman，得把这一节重跑一遍。

## 已知会变差的地方

- **粘图片。** 浏览器终端内使用 Windows / Linux 的 `Ctrl+V` 或 Mac 的 `⌘V`。
  图片先显示预览，可移除或补充说明；点击「上传图片」后，再由学生点击「插入当前会话」，
  检查输入框并按 Enter 发送。图片保存在所选项目的 `uploads/` 中，单次最多 8 张，
  支持 PNG / JPEG / GIF / WebP，单张不超过 64 MiB。文字粘贴保持终端原有行为。
  网页底部按客户端系统显示粘贴快捷键；`F5` 保留刷新页面，本地版仍用 `F5` 粘图片。
  `entrypoint.sh` 只给 ttyd 启动的 TUI 设置 `DCT_BROWSER_TERMINAL=1`，让 TUI 不再重复显示本地粘贴提示。
- **中文输入法、Ctrl 组合键、复制粘贴。** 浏览器终端跟本地终端不是一回事，
  这三样具体差多少要人在真设备上试，还没试。
- **一个容器一个人。** 谁连得上 `~/.dct/daemon.sock`，谁就能以那个身份执行任意
  命令。一个容器塞多个学生 = 互相能进对方的会话、读对方的密钥。这条不做取舍。
  镜像里那条 `safe.directory '*'` 的安全性也建立在它上面。
- **学生自己提交时的署名是个占位符**：镜像在 `--system` 层配了
  `dc-workspace user <user@dc-workspace.local>`，好让他 `git commit` 得成，
  而不是撞一句英文报错。**这一期学生的 git 只做本地提交**，那份历史不流到
  别人那里，所以占位署名的代价是可接受的。他自己
  `git config --global user.email/user.name` 之后，他那份就赢。
  **dct 的检查点跟这个无关**——它用的是自己的署名（`dct <dct@localhost>`，
  环境变量压过所有配置），改这两行不会影响撤销。

## 起第二份、第三份……

**宿主那一侧的端口要换**，否则第二份直接
`Bind for 127.0.0.1:7681 failed: port is already allocated`：

```sh
DCW_HOST_PORT=7691 docker compose -p 学生2 -f container/compose.yaml up -d
```

项目名（`-p`）不同，卷名也跟着不同，两份的状态天然不共享。`DCW_PUBLIC_URL`
不给的话会跟着 `DCW_HOST_PORT` 走，所以链接印出来就是对的。

**两份之间隔离到什么程度**（2026-09-07 起两份真跑出来的）：

| | |
|---|---|
| 钥匙 | 各自一把，互相打不开对方的门（都是 401） |
| 会话 | `dct ps` 只看得见自己的 |
| 密钥仓 / 对话记录 / 代码 | 三个卷各一套，`secrets.toml` 的 md5 都不一样 |
| 文件系统 | 各自只看得到自己的 `/home/dc` |
| **网络** | **通的——别拿它当隔离**（见下） |

**网络上两个容器互相够得着**：从学生 2 的容器里能连上学生 1 的 `7681`。
拦住他的是**那道门**（不带钥匙、带自己的钥匙，都是 401），不是网络。
而真正能给出终端的 ttyd 在 `7682` 上**只绑容器内环回**，邻居连不到——
所以「ttyd 绑 127.0.0.1」那个决定是承重的，不是好看。

要真正的网络隔离（同一台机器上跑很多份、且不信任其中任何一份），那是起容器
的人的事：`internal` 网络、或者防火墙规则。**这个镜像不提供网络隔离，别假设
它有。**

## 内存

2026-09-07 实测（`docker stats`，两份并排跑着比出来的）：

| | |
|---|---|
| 底座（daemon + ttyd + gate + tini，0 个会话） | **22.6 MiB** |
| 再加一个**闲着的** claude 会话 | **105 MiB**（净增约 82） |

定 `mem_limit` 不能用上面这个数——闲着的 agent 还没装进任何上下文。**干活时**
那个数是根目录 README 里实测的约 320 MB/agent。按「一个人同时开三个」算：
23 + 3×320 ≈ 1 GB，`compose.yaml` 里的 `2g` 留了一倍余量给峰值。

**这个数字是单人的。三十个人是三十个容器，不是把 `mem_limit` 调大。**

## 跟随 agent 的浅色 / 深色主题

在 Claude 或 Codex 里用 `/theme` 保存内置主题后，dct 会在约半秒内同步
默认文字和背景的深浅。浏览器终端也会跟着切换；切换会话时跟随新会话的
agent，回到看板时恢复终端原来的配色。错误、代码高亮等 agent 明确指定的
颜色，以及 F6 选的标题栏颜色仍然保留。

跟随的是保存后的选择，不是主题选择器里还没确认的预览。自动模式、未知
主题、自定义主题和自定义 profile 暂时保留终端自己的默认颜色；`NO_COLOR`
会关闭跟随。原生终端只改变 dct 画面，不修改终端应用的全局配色。

## 学生项目库与下载（首期）

右侧「项目与文件」提供真实文件列表、上传、单文件下载、项目 ZIP 下载、
保存归档、新建项目和继续项目。「我的项目」列出当前工作区保留的项目。
旧的 `/home/dc/work` 自动登记为「原有项目」，不移动或清空其中的文件。
新项目位于 `/home/dc/.dct/student-projects/work/<项目编号>`；最近一次归档
和项目记录在同级的 `archives/` 与 JSON 文件中。保留 `.dct` 和 `work`
两个卷才能同时保留新旧项目。不要对包含学生作品的部署执行 `down -v`。

页面显示的是服务器确认的**上次归档时间**，不是 agent 尚未落盘内容的
保存承诺。代码写入项目目录后由持久化卷保留；关闭浏览器不会清掉作品。
「保存归档」保存导出范围内的文件。下载项目会重新准备 ZIP，只有完整
归档校验通过后才开始传输；文件正在变化时请稍后重试。下载不会删除项目。

「结束本次练习」先验证可归档，再停止该项目下的 dct 会话，再保存最后
文件状态。停止会话会中断正在进行的 agent 请求。任一步失败都保留原文件；
最后归档失败时会话可能已停止，页面会明确提示重试保存。此操作不删除项目、
依赖或缓存，也不声称清理自行脱离 dct 会话的后台程序。继续项目会创建或
复用所选 agent 的会话，然后在终端看板选择提示的会话编号。

导出排除 `.env*`、常见账号配置、私钥文件、Git 内部目录、依赖与缓存、
符号链接和硬链接。上传素材包含在导出中；文件名规则不能识别源码里手写的
密钥，分享前仍需检查源码。上传单文件限 64 MiB，同名不覆盖；每次归档
最多 128 MiB / 10,000 个文件 / 32 层目录，项目最多 100 个，归档临时空间
与保留归档的总预算为 512 MiB。这是归档操作限制，**不是终端写入的磁盘配额**；
宿主机仍需配置磁盘监测/配额。3 GiB 内存限制与项目存储无关。

同一条工作区链接的使用者共享项目库。为不同学生分配独立容器、卷和工作区
链接，才能隔离作品。单卷持久化不等于异机备份。首期没有项目删除、命名版本、
ZIP 导入或回收站按钮。
