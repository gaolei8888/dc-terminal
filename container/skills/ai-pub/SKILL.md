这是 DCT 各 agent 共用的 ai-mania 学生作品发布流程，网站是 https://ai.tzspace.cn。它不负责 ai-mania 网站本身的开发、运维或部署。

先确认 `command -v dct-publish` 成功，且当前环境已由 DCT 配置工作区发布权限。若命令不存在或报告未配置发布凭据（例如普通本机开发会话），说明需要进入 dataclue.cn 的学生工作区使用发布功能；不要复制其他工作区凭据，也不要把本机目录误当成服务器目录。

使用已安装的 `dct-publish`。它仅使用当前工作区的发布凭据；不要读取或展示 `~/.dct/publish.json`，不要寻找网站管理员、SSH 或其他学生的凭据。

1. 找到当前项目的静态产物目录。项目在 `/home/dc/work` 或 `~/.dct/student-projects/work/<项目编号>`；以实际目录为准。若需构建，完成构建再准备上传。Vite 使用相对基址（例如 `npm run build -- --base=./`）；检查 HTML、CSS 和脚本的根绝对资源路径，改成适配子目录的相对路径。预览链接不能是 localhost。
2. 只提交可独立打开的静态产物，根目录需要 `index.html`。排除源代码配置、依赖目录和 sourcemap；移除密钥、登录配置、`.env`、符号链接和硬链接。最多 5000 个文件、100 MiB。需要数据库或后端运行时的应用不能直接发布：说明缺少的能力，保留原项目；未经用户同意，不把真实功能替换成演示数据。
3. 执行 `dct-publish prepare --dir "实际静态目录" --title "作品标题" --summary "简短说明"`。这一步准备持链接可访问、七天有效的预览，不公开发布。仅采用返回的 `previewUrl`、`confirmUrl`、`version` 和 `status`；不能猜测、拼接链接或宣称已上线。
4. 给学生可点击的预览和确认链接，说明“预览已准备好，请检查后在确认页面提交发布/审核”。公开提交由学生在页面操作；不要用 CLI、HTTP 请求或浏览器自动点击代替这个确认。
5. 查看进度使用 `dct-publish status --version "返回的版本编号"`，按服务实际状态说明结果。超时、断线或无效响应时，准备操作结果可能未知：不要盲目重复上传；有版本号则查询状态，否则如实说明未收到版本号，请老师核查服务端记录。没有实际返回的链接时，如实报告未拿到链接。
